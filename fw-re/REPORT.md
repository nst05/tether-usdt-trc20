# Реверс-инжиниринг прошивки встроенного устройства (MSP430F249)

Отчёт по исследованию бинарной прошивки `razbor.hex`. Работа выполнена по
задачам дипломной работы: восстановлены архитектура, структура программы,
обработчики прерываний, константы и таблицы, алгоритмы обработки данных,
интерфейсы связи и протокол обмена; разработано и проверено программное
обеспечение для взаимодействия с устройством.

Все результаты воспроизводимы инструментами каталога `tools/` и `host/`.

---

## 1. Анализ исходного файла и архитектура микроконтроллера

**Формат файла.** `razbor.hex` — текстовый Intel HEX (3842 записи, CRLF).
Разбор выполняет `tools/ihex.py` с проверкой контрольных сумм всех строк
(ошибок не обнаружено).

**Карта образа памяти:**

| Область | Адреса | Размер | Содержимое |
|---|---|---|---|
| Information memory | `0x1000–0x10FF` | 256 Б | Калибровки, служебные параметры |
| Main flash (код) | `0x1100–0xFFDF` | ≈60 КБ | Программа |
| Заводские DCO-калибровки | `0x10F8–0x10FF` | 8 Б | `CALBC1_*/CALDCO_*` |
| Таблица векторов | `0xFFE0–0xFFFF` | 32 Б | 16 векторов прерываний |

**Вывод об архитектуре.** Совокупность признаков однозначно указывает на
**Texas Instruments MSP430F249** (семейство MSP430F2xx, ядро MSP430 16 бит,
фон-Неймановская адресация, little-endian):

- информационная flash-память по адресу `0x1000` и главная flash `0x1100–0xFFFF`
  (ровно 60 КБ) — карта памяти F249;
- таблица из 16 двухбайтных векторов в самом верху адресного пространства;
- заводские константы калибровки DCO в конце информационной памяти;
- код содержит обращения к периферии F2xx: `ADC12`, аппаратный умножитель
  `MPY/MPYS/MAC`, `Timer_A3`, `Timer_B7`, два модуля `USCI` (A0/B0 и A1/B1),
  контроллер flash `FCTL1/2/3` с ключом `FWKEY=0xA5xx`.

Модель подтверждена пользователем: **MSP430F249**.

## 2. Дизассемблирование и структура программы

Готового дизассемблера MSP430 в окружении нет (Capstone эту архитектуру не
поддерживает), поэтому реализован собственный — `tools/msp430.py`:

- все три формата команд MSP430 (двух-, одно­операндные, переходы);
- генератор констант (`R2/R3`), все режимы адресации;
- распознавание эмулируемых мнемоник (`RET`, `POP`, `BR`, `CLR`, `INC`,
  `TST`, `RLA`, `EINT/DINT` и др.);
- карта регистров периферии F2xx для читаемых имён (`&P5OUT`, `&UCA0TXBUF`…).

Рекурсивный обход (`tools/analyze.py`) от всех векторов прерываний с
последующей линейной досборкой дал:

- **16 077 распознанных команд**, покрытие кода **97.8 %**;
- **168 функций** с восстановленными перекрёстными ссылками (кто кого вызывает);
- полный листинг `razbor.lst` (~20 000 строк) с именами функций, метками
  переходов и списками вызывающих.

## 3. Программные модули, обработчики прерываний, функциональные блоки

### 3.1. Таблица векторов и назначение обработчиков

Назначение каждого вектора установлено **экспериментально** — по регистрам
периферии, к которым обращается тело обработчика:

| Вектор | Адрес | Точка входа | Назначение (по коду) |
|---|---|---|---|
| RESET | `0xFFFE` | `0x1100` | Инициализация (WDT, порты, тактирование, USCI) |
| NMI | `0xFFFC` | `0x2532` | Отказ генератора: `IFG1.OFIFG`, `BCSCTL2` |
| WDT | `0xFFF4` | `0x2560` | Сторожевой таймер |
| Timer_A0 | `0xFFF2` | `0x2DC6` | `TACCTL0/TACCTL2` — генерация битов передачи |
| Timer_A1 | `0xFFF0` | `0x2F12` | `ADD &TAIV,PC` — векторизация по `TAIV` |
| Timer_B1 | `0xFFF8` | `0x2570` | `TBCCTL1/TBCCTL6` — тайминги измерения |
| ADC12 | `0xFFEA` | `0x3CC2` | Чтение `ADC12MEM0..3`, расчёт величин |
| USCI A0/B0 RX | `0xFFEE` | `0x2E32` | Приём по UART-каналу 0 (`UCA0RXBUF`) |
| USCI A0/B0 TX | `0xFFEC` | `0x2E72` | Передача по каналу 0 (`UCA0TXBUF`) |
| USCI A1/B1 RX | `0xFFE2` | `0x2EA2` | Приём по UART-каналу 1 (`UCA1RXBUF`) |
| USCI A1/B1 TX | `0xFFE0` | `0x2EE2` | Передача по каналу 1 (`UCA1TXBUF`) |
| PORT2 | `0xFFE6` | `0x4412` | **Кнопки** (`P2IFG.6`) |
| Comparator_A, Timer_B0, Port1, рез. | — | `RETI` | Заглушки (не используются) |

### 3.2. Основные функциональные блоки

- **Измерительный блок** (ISR ADC12 `0x3CC2`): 4 аналоговых канала
  (`ADC12MEM0..3`), знаковое умножение через `MPYS/OP2` для расчёта квадратов
  величин (действующие значения), накопление энергии в 40-битном аккумуляторе
  `0x03E4:0x03E6`. Устройство относится к классу измерительных приборов.
- **Коммуникационный блок**: два симметричных UART-канала с кольцевыми
  буферами приёма/передачи (буферы `0x0810…` и `0x04B0…`, указатели `0x0828`
  и `0x04A4`, флаги состояния `0x082B` и `0x04A7`).
- **Блок обработки протокола** (`sub_823E`): единый разборщик кадра для всех
  каналов, диспетчер команд (`0x8474`), обработчики функций.
- **Блок клавиатуры** (ISR PORT2 → `sub_4D76/50B4/537E`): три виртуальных
  канала обработки нажатий.
- **Блок хранения** (`sub_80xx`): запись параметров/калибровок во flash через
  `FCTL` (стирание сегмента `FWKEY+ERASE=0xA502`, запись `FWKEY+WRT=0xA540`).
- **Программный I²C** (`sub_C2E2/C3A2/C3DC…`): bit-bang-обмен с внешней
  последовательной памятью (SDA/SCL на выводах порта, тайминги `TBCCTL6`),
  16-битный адрес, постраничная запись.

## 4. Коэффициенты, константы, таблицы и области их хранения

| Объект | Адрес | Назначение |
|---|---|---|
| `auchCRClo` (256 Б) | `0xFB3C` | Таблица CRC-16/Modbus (младший байт) |
| `auchCRChi` (256 Б) | `0xFC3C` | Таблица CRC-16/Modbus (старший байт) |
| Заводские DCO-калибровки | `0x10F8–0x10FF` | Настройка тактового генератора |
| Калибровки/параметры устройства | `0x1000–0x10F7` | Перезаписываемые коэффициенты |
| Таблица переходов команд | `0x8474` | 9 записей `BR #handler` |
| Битовые таблицы конфигурации | `0x07D0`, `0x07D7` | Настроечные маски (функция 0x00) |
| Собственный адрес устройства | ОЗУ `0x04FE` | Адрес в кадре протокола |
| Аккумулятор энергии | ОЗУ `0x03E4:0x03E6` | 40-бит накопление |
| Начальное значение XOR-суммы | константа `0xF0F0` | КС служебных структур |

Таблицы CRC расчётно эквивалентны стандартным `auchCRCHi/auchCRCLo` (полином
`0xA001`) — проверено тестом `test_tables_match_firmware`.

## 5. Восстановленные алгоритмы обработки и расчёта данных

### 5.1. Контрольная сумма кадра — CRC-16/Modbus

Функции `sub_BBF6` → `sub_BC22`. Внутренний цикл:

```
idx = data_byte XOR (crc >> 8)
crc = ((crc_lo XOR tabA[idx]) << 8) | tabB[idx]      ; tabA=0xFB3C, tabB=0xFC3C
```

Начальное значение `0xFFFF`. Внутренний регистр прошивки хранит
**байт-инвертированное** значение стандартной свёртки; в кадр (сравнение в
`sub_83A2`) CRC уходит **младшим байтом вперёд** — это в точности CRC-16/Modbus.
Эквивалентность доказана экспериментально (`test_crc_equivalent_to_modbus`,
`test_firmware_algorithm_bytewise`).

### 5.2. Контрольная сумма служебных структур — XOR

`sub_4A72` / `0x7C58`: `csum = 0xF0F0 XOR w0 XOR w1 XOR w2` (три 16-битных
слова). Используется для внутренних пакетов и обмена с внешней памятью.

### 5.3. Обработка измерений

ISR ADC12: `x² = MPYS·OP2`, накопление в `RESHI:RESLO`, суммирование в
40-битный аккумулятор, масштабирование калибровочными коэффициентами при
формировании результата.

## 6. Органы управления и обработка нажатий кнопок

Кнопки заведены на **порт P2, линия 6** (флаг `P2IFG.6`, вектор PORT2
`0x4412`). Обработчик:

1. проверяет и сбрасывает `P2IFG.6`, разрешает прерывания (`EINT`);
2. по флагам «нажато» (бит 4 в словах `0x027C`, `0x028C`, `0x029C`)
   выбирает один из трёх обработчиков нажатия — `sub_4D76`, `sub_50B4`,
   `sub_537E`;
3. обработчики реализуют антидребезг (счётчики), «короткое/длинное» нажатие
   (сравнение `0x043C` с `0x0316`, установка бит `0x0200/0x1000/0x1200` в
   слове состояния) и переключение режимов/меню.

**Возможность переназначения.** Логика нажатий сосредоточена в трёх функциях с
чёткими точками ветвления; изменение существующих и добавление новых функций
кнопок технически возможно правкой этих обработчиков (разд. 10).

## 7. Интерфейсы связи

- **Два независимых UART** (USCI_A0 и USCI_A1), 8N1. Параметры из инициализации:
  `UCAxCTL1=0xE1` (источник SMCLK), делители `{0xC4,0x09}` и `{0x71,0x02}` —
  стандартные скорости обмена (порядка 9600 бод при SMCLK≈1 МГц). Каждый канал
  снабжён кольцевым буфером и полудуплексным управлением направлением
  (`P5OUT`/`P2OUT` — вероятно RS-485 DE/RE).
- **Программный I²C** (bit-bang) — обмен с внешней энергонезависимой памятью.
- Дискретные линии портов P1–P6 — индикация, управление, чтение кнопок.

## 8. Протокол обмена: кадры, команды, идентификаторы, контроль

Разборщик `sub_823E` (общий для каналов). **Структура кадра** — Modbus RTU-совместимая:

```
+--------+--------+------------------+---------+---------+
| addr   | func   |     данные…      | CRC_lo  | CRC_hi  |
+--------+--------+------------------+---------+---------+
  byte0    byte1        N байт        CRC-16/Modbus (LE)
```

- **addr** — адрес устройства (собственный в `0x04FE`); `0x00` и `0xFE` —
  широковещательные (`0x833A…0x834E`);
- **func** — код функции `0x00…0x08`, диспетчеризация таблицей `0x8474`
  (`index·4 + PC`);
- **CRC-16/Modbus**, младший байт вперёд.

**Карта функций** (по обработчикам):

| func | Обработчик | Назначение |
|---|---|---|
| `0x00` | `0x8498` | Установка битовой конфигурации (таблицы `0x07D0/0x07D7`) |
| `0x01` | `0x84F4` | Выбор режима / сохранение (подкоманда в байте данных) |
| `0x02` | `0x8590` | Сброс служебного флага `0x02A1` |
| `0x03` | `0x85B2` | Проверка адреса / служебная (эхо) |
| `0x04` | `0xA0FE` | **Чтение** параметра/области |
| `0x05` | `0xA3B6` | **Запись** параметра |
| `0x06` | `0xA7C6` | Блочная операция (длина/индекс в байте 5) |
| `0x07` | `0xAAEC` | Расширенная операция (длина = байт5 + 8) |
| `0x08` | `0xAD98` | Доступ к **калибровочным** параметрам (подкоманды `0x01` чтение, `0x12` запись) |

Перед диспетчеризацией проверяются длина, адрес и CRC; при несовпадении CRC
кадр молча отбрасывается (в передатчик — `0x85C0 → 0xB8D0`).

**Команды чтения/изменения параметров** формируются высокоуровневыми
построителями `host/protocol.py`: `read_param` (func 0x04),
`write_param` (func 0x05), `read_calibration`/`write_calibration` (func 0x08).

## 9. Разработанное ПО и экспериментальная проверка

### 9.1. Состав ПО (`host/`)

- `protocol.py` — реализация протокола: CRC-16/Modbus, XOR-сумма, класс
  `Frame` (сборка/разбор), коды функций, построители команд;
- `device.py` — клиент: транспорт `SerialTransport` (pyserial, реальный UART)
  и высокоуровневые операции чтения/записи параметров и калибровок;
- `emulator.py` — программный эмулятор устройства, воспроизводящий
  диспетчеризацию `sub_823E`, для проверки без «железа»;
- `cli.py` — утилита командной строки (`build`, `parse`, `read`, `write`,
  `cal-read`, `cal-write`), работает и с портом, и с эмулятором;
- `tests/test_protocol.py` — 10 автоматических тестов.

### 9.2. Экспериментальная проверка (10/10 тестов пройдено)

- **CRC-16 из прошивки == стандарт Modbus** — сверка табличного алгоритма
  прошивки и сдвиговой эталонной реализации на нескольких сообщениях;
- **таблицы прошивки == восстановленные `auchCRClo/hi`** — побайтовое сравнение
  с `0xFB3C/0xFC3C`;
- **байт-инверсия внутреннего регистра** — прямая эмуляция цикла `sub_BC22`;
- **XOR-сумма** `0xF0F0 ^ …` — сверка с `sub_4A72`;
- **сборка/разбор кадра и обнаружение искажений** по CRC;
- **чтение/запись параметров и калибровок** через эмулятор;
- **фильтрация по адресу и широковещание**.

Запуск:

```bash
python3 host/tests/test_protocol.py        # или: python3 -m pytest host/tests/
python3 host/cli.py cal-read --emulate --addr 1 --param 0
```

Для работы с реальным устройством: подключить USB-UART, указать `--port` —
клиент отправит команду, примет ответ, проверит CRC и расшифрует поля кадра.

## 10. Предложения по расширению функциональности

1. **Переназначение кнопок.** Обработчики `sub_4D76/50B4/537E` и таблица
   переходов команды `0x00` (`0x07D0/0x07D7`) позволяют изменить реакции на
   короткое/длинное нажатие и добавить новые действия (например, быстрый вызов
   калибровки или смену канала индикации).
2. **Расширение протокола.** В таблице `0x8474` заняты коды `0x00…0x08`;
   свободные значения (после расширения проверки длины) можно задействовать под
   новые команды — потоковую выдачу измерений, чтение журналов, самодиагностику.
3. **Пользовательский интерфейс хоста.** На базе `host/protocol.py` возможна
   надстройка с GUI: живой мониторинг измерений, редактор калибровочных
   коэффициентов, сохранение/загрузка профилей настроек, автоматическая
   калибровка.
4. **Диагностика и логирование.** Добавить команду выгрузки внутренних
   счётчиков ошибок связи и статуса каналов через свободный код функции.

## Приложение. Как воспроизвести

```bash
cd fw-re
python3 tools/ihex.py     razbor.hex          # карта памяти
python3 tools/analyze.py  razbor.hex          # векторы, функции, периферия
python3 tools/listing.py  razbor.hex razbor.lst   # полный листинг
python3 tools/strings_scan.py razbor.hex 6    # строки/таблицы
python3 host/tests/test_protocol.py           # экспериментальная проверка
```

Каталоги: `tools/` — средства реверс-инжиниринга, `host/` — ПО обмена,
`razbor.lst` — дизассемблированный листинг, `fw-re-analysis.txt` — сводка анализа.
