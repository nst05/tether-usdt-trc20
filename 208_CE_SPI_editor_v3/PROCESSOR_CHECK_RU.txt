ПРОВЕРКА ТРЁХ ПРОЦЕССОРНЫХ ПРОФИЛЕЙ — CE208 SPI EDITOR 3.1.0

Проверенные дампы
1. C:\ce208\24cl64.bin
   SHA-256: 0344BD86DF39A9DB3F23AB0EF89820CAB5D27C255349E51C30AD112AF39C88C2
2. C:\ce208\codex\24C64_MKMSP430.bin
   SHA-256: 118BE6E72B1CB2A4AD2E8B41A00FD1BA8857890342C1907CB85025AAC12A5F9F

Что совпадает
- текущие банки: 0x0020 + bank*0x44;
- зеркала: 0x1A00 + bank*0x44;
- четыре банка 0..3;
- запись 0x44 байта: 13 ячеек u40le, marker, CRC little-endian;
- T1..T8 находятся в ячейках 3..10;
- пары направлений: 0/2 и 1/3.

Что отличается
- V8530: low16 от CRC-32 MSB-first, poly 0x04C11DB7,
  init 0xFFFFFFFF, без final XOR;
- профиль MSP4xx: CRC-16 CCITT poly 0x1021, входной байт bit-reversed,
  init 0x68D3, без output XOR.

Результат проверки
- V8530: 46 служебных + 8 энергетических копий валидны только по V8530 CRC;
- MSP4xx: те же 46 + 8 копий валидны только по MSP CRC;
- перекрёстных совпадений: 0;
- тестовая запись второй пары 1/3 сформирована и проверена в обоих профилях,
  primary и backup имеют CRC выбранного процессора.

Защита редактора
- «Авто» разрешает запись только при однозначном определении профиля;
- неправильный ручной выбор процессора блокирует запись;
- пустой/повреждённый дамп в «Авто» блокируется — процессор надо выбрать вручную;
- эта проверка действует перед всеми операциями, которые изменяют записи.

Примечание: имя второго предоставленного файла содержит MSP430, а прежний интерфейс
называет профиль MSP432. По EEPROM достоверно определяется формат хранения и CRC MSP4xx;
точная маркировка кристалла определяется по плате/прошивке, не по EEPROM-дампу.


ТРЕТИЙ ПРОФИЛЬ — STM32 (добавлен в 3.1.0)
Проверенный дамп: stm32l162ret_fm24cl64.bin (FRAM FM24CL64, 8 КиБ).

Контрольная сумма записи
- тело идёт 16-битными словами little-endian: слово складывается по модулю 2
  с младшими битами 32-битного регистра, затем 32 сдвига с полиномом 0x04C11DB7;
- начальное значение 0xFFFFFFFF, финального XOR нет, в запись пишутся младшие
  16 бит little-endian.

Отличие раскладки
- резервная копия смещена на 0x1B98 (у V8530 и MSP4xx — 0x19E0):
  область 0x0000..0x0467 дублируется в конец FRAM.

Результат проверки
- время, tariff_control и все четыре энергетических банка сходятся по STM32 CRC
  в основной копии и в зеркале; перекрёстных совпадений с V8530 и MSP4xx нет
  (счёт автоопределения: STM32 16, V8530 0, MSP4xx 0);
- тестовая запись обеих групп (банки 0/2 и 1/3) сформирована и перечитана:
  суммы совпали с независимым расчётом и в основной копии, и в зеркале;
- часть статических записей карты V8530 (журналы, счётчики, часть cfg) в прошивке
  STM32 расположена по другим адресам — они помечаются как «нет области».
