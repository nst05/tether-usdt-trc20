# FRAM Patcher — Android (BLE)

Kotlin + Jetpack Compose приложение для управления платами ESP32-WROOM-32D
(прошивка из `esp32_fram_patcher/`) по Bluetooth Low Energy. Функционал —
те же 3 режима, что в PyQt5-утилите/веб-версии.

## Почему BLE, а не классический Bluetooth с системным PIN

Начиная с Android 6+ приложение не может программно задавать/подтверждать
PIN системного диалога сопряжения (Classic Bluetooth SPP, как у HC-05) —
для этого нужно системное разрешение `BLUETOOTH_PRIVILEGED`, недоступное
обычным приложениям. Поэтому здесь используется **BLE с авторизацией на
уровне приложения**: подключение по GATT без стандартного сопряжения ОС,
а PIN проверяется самой прошивкой через отдельную характеристику. Это даёт
полный контроль над PIN именно в этом приложении.

Плюс: PIN каждой платы уникален и хранится в NVS-памяти самой платы (не в
приложении), меняется через экран «Настройки» после подключения.

## Экраны

1. **Сканирование** — поиск плат (фильтр по UUID сервиса, видны только
   платы с этой прошивкой), имя вида `FRAM-XXXX`, кнопка «Подключить».
   Если Bluetooth выключен — сверху показывается баннер с кнопкой
   «Включить Bluetooth» (системный запрос, одно нажатие), а кнопка поиска
   заблокирована до включения. Баннер исчезает сам, когда адаптер включён
   (в т.ч. если включить его из шторки — приложение слушает изменения
   состояния через `BluetoothAdapter.ACTION_STATE_CHANGED`).
2. **Ввод PIN** — после GATT-подключения нужно ввести PIN платы
   (по умолчанию `123456` на новой прошивке).
3. **Главный экран** — 3 вкладки (Режим 1/2/3), повторяют функционал
   веб/PyQt версии: чтение из FRAM, расчёт производных полей (k-режимы,
   авто-расчёт второго канала/суммы), запись обратно.
4. **Настройки** — смена PIN текущей платы (нужен старый + новый).

## Разрешения

Приложение запрашивает при первом запуске:
- Android 12+ (`API 31+`): `BLUETOOTH_SCAN`, `BLUETOOTH_CONNECT`
  (без гео — используется флаг `neverForLocation`)
- Android ≤11: `ACCESS_FINE_LOCATION` (обязательное системное требование
  для BLE-сканирования на старых версиях, не используется приложением
  по назначению)

## Сборка

Открой папку `FramPatcherBLE/` в Android Studio (Hedgehog и новее) —
она сама подтянет Gradle Wrapper и зависимости. Либо вручную:

```bash
cd FramPatcherBLE
gradle wrapper --gradle-version 8.5   # если нет gradlew — сгенерировать один раз
./gradlew assembleDebug
```

APK появится в `app/build/outputs/apk/debug/`.

⚠️ Проект не проверялся реальной сборкой (в этой среде нет доступа к
Android SDK/Google Maven), только через ручную сверку кода. Если Android
Studio подсветит несовпадение версий (AGP/Kotlin/Compose BOM) — прими
предложенный автоапгрейд, это нормально, экосистема обновляется часто.

## Протокол (совпадает с прошивкой)

UUID сервиса и характеристик — в `ble/BleConstants.kt`, должны буквально
совпадать с `include/config.h` прошивки. Если меняешь один — меняй и другой.

Порядок работы `BleManager`:
1. `startScan()` — фильтр по UUID сервиса.
2. `connect(device)` — GATT-подключение, запрос MTU 247, discovery,
   включение notify на характеристике `RESP`.
3. `authenticate(pin)` — пишет PIN в `AUTH`, ждёт ответ `{"ok":true/false}`.
4. `sendCommand(json)` — пишет JSON в `CMD`, ждёт ответ через `RESP`.
5. `setPin(old, new)` — смена PIN через `SETPIN`.

Запросы идут строго последовательно (внутренний `Mutex`) — это важно,
так как прошивка не поддерживает параллельные команды.

## Известные ограничения / что стоит доделать

- PIN не сохраняется в приложении между сессиями (осознанно, для
  безопасности) — вводится каждый раз при новом подключении. Если хочешь
  «запомнить меня» — добавь `EncryptedSharedPreferences`
  (`androidx.security:security-crypto`) для конкретного адреса устройства.
- Список найденных устройств не различает несколько плат с одинаковым
  именем (маловероятно благодаря суффиксу из MAC, но адрес BLE всегда
  уникален и показан под именем).
- BLE-запись символов только ASCII/UTF-8 (JSON) — двоичные данные не
  передаются, только текстовые команды/ответы, что соответствует
  протоколу прошивки.
