# Инструкция по использованию

Как пользоваться программами анализа и работы с прибором **MSP430FE427**.
Все команды даны для Windows (в скобках — для Linux/Mac).

---

## 0. Что нужно один раз установить

1. **Python 3** (если ещё нет) — с python.org. При установке поставить галочку
   «Add Python to PATH».
2. Для обмена с прибором по порту — библиотека **pyserial**:
   ```
   pip install pyserial
   ```
   Для дизассемблера и редактора дампа ничего ставить не нужно — только Python.

Проверить, что Python виден:
```
python --version
```

Все команды ниже запускаются из папки `firmware_analysis` (перейти в неё:
`cd C:\...\firmware_analysis`).

---

## 1. Из чего состоит проект

| Файл | Что делает |
|------|-----------|
| `dumpedit.py` | **редактор коэффициентов в дампе** с ползунками (окно) |
| `gui.py` | **общение с прибором** по UART (окно) |
| `protocol.py` | то же общение, но из командной строки + библиотека |

| `README.md` | полный технический разбор (для диплома) |
| `firmware/` | сама прошивка (`.hex` и `.s19`) |

## 2. Редактор коэффициентов `dumpedit.py` (ползунки)

Меняет калибровку **в файле дампа** (перед перепрошивкой).

**Запуск:**
```
python dumpedit.py
```
или сразу с файлом:
```
python dumpedit.py firmware\201.2_2.s19
```

**Порядок работы:**
1. Нажать **«Открыть дамп…»** и выбрать файл `.s19` или `.hex`.
2. Появятся три ползунка:
   - **ADAPTI1 (0x1000)** — общий аппаратный коэффициент;
   - **Масштаб напряжения (0x1002)**;
   - **Масштаб тока (0x1004)**.
3. Двигать ползунок **или** вписать точное число в поле **Значение** (DEC)
   либо **HEX**. Под каждым ползунком видно:
   - *множитель к оригиналу* — например `×0.500 (−50.0%)` значит показания
     станут вдвое меньше;
   - *Учёт энергии* — насколько ускорится/замедлится учёт: например
     «МЕДЛЕННЕЕ на 50.0% (счётчик отстаёт, занижает)» красным/синим цветом;
   - исходное значение («было …»).
4. Кнопка **«Сброс»** возвращает коэффициент к исходному.
5. **«Сохранить как…»** — сохранить в **новый** файл.

**Что важно:**
- Программа **не даёт перезаписать оригинал** и при первом сохранении сама
  делает резервную копию (`имя.s19.bak`).
- Меняются только отредактированные байты, всё остальное в дампе остаётся
  нетронутым, контрольные суммы строк пересчитываются автоматически.
- Дальше изменённый файл прошивается в прибор программатором (MSP-FET,
  FET-Pro430) — см. отчёт руководителя.

> Коэффициенты — это заводская калибровка. Меняй только с резервной копией.

## 3. Общение с прибором `gui.py` (окно)

Отправка команд прибору по последовательному порту (USB-UART, TTL 3.3 В,
9600 бод, 8N1).

**Запуск:**
```
python gui.py
```

**Порядок работы (сверху вниз по окну):**

**1. Соединение**
- В **COM-порт** выбрать порт адаптера (кнопка «Обновить» перечитывает список;
  номер порта видно в Диспетчере устройств Windows).
- **Скорость** оставить `9600`.
- **Адрес прибора** — по умолчанию `04 A2 CB 71`. Если не знаешь адрес —
  нажми **«Найти прибор»** (широковещательный поиск, прибор сам сообщит ID).
- Нажать **«Открыть порт»**.

**2. Команда**
- Выбрать команду из **выпадающего списка** — они на понятном языке, напр.
  «Прочитать показания: напряжение, ток, энергию». Под списком — пояснение,
  что команда делает.
- Нажать **«▶ Отправить»**.

**3. Журнал** — показывает отправленный запрос (синим) и ответ прибора
(зелёным; красным — если ошибка или неверная CRC). Для команды показаний
сразу расшифровывается напряжение.

**Без прибора:** если порт не открывать, кнопка «Отправить» просто соберёт и
покажет кадр — удобно, чтобы посмотреть протокол.

**Про команды записи** (помечены `[ЗАПИСЬ]`, оранжевым): они меняют память
прибора и требуют подтверждения в диалоге. Не отправляй их на рабочий прибор
без резервной копии.

## 4. Командная строка `protocol.py` (без окна)

Показать список всех команд:
```
python protocol.py --list-commands
```

Собрать кадр и посмотреть его (без прибора):
```
python protocol.py --build --addr 04A2CB71 --cmd 0x63
```

Разобрать принятый дамп кадра:
```
python protocol.py --parse "04 A2 CB 71 63 23 05 00 12 00 00 45 9A 1B"
```

Поиск прибора через реальный порт:
```
python protocol.py --port COM3 --discover
```

Прочитать показания с прибора:
```
python protocol.py --port COM3 --addr 04A2CB71 --read 0x63
```

Команда записи требует явного `--write` (защита от случайной записи):
```
python protocol.py --port COM3 --addr 04A2CB71 --cmd 0x41 --data "1F C5 00 00" --write
```

## 5. Дизассемблер `msp430dis.py`

Готовый разбор уже лежит в `disasm.lst`. Пересобрать при желании:

```
python msp430dis.py firmware\201.2_2.hex --map          (карта памяти и векторы)
python msp430dis.py firmware\201.2_2.hex --sfr          (какие регистры используются)
python msp430dis.py firmware\201.2_2.hex -o disasm.lst  (полный листинг в файл)
```

## 6. Типовые сценарии

**Посмотреть текущую калибровку прибора, ничего не меняя:**
`python gui.py` → открыть порт → команда «Прочитать калибровку напряжения и
тока» (0x51) → посмотреть ответ в журнале.

**Изменить коэффициент тока в дампе и подготовить файл для прошивки:**
`python dumpedit.py firmware\201.2_2.s19` → сдвинуть ползунок «Масштаб тока» →
«Сохранить как…» → получить `201.2_2_edited.s19` → прошить программатором.

**Снять показания прибора:**
`python gui.py` → открыть порт → команда 0x63 → в журнале появятся напряжение,
ток, энергия.

## Если что-то не работает

- **`python не является внутренней командой`** — Python не в PATH; переустановить
  с галочкой «Add Python to PATH» или запускать через `py` вместо `python`.
- **Окно не открывается, ошибка про `tkinter`** — установить модуль Tk
  (в Windows он обычно уже есть; в Linux: `sudo apt install python3-tk`).
- **`No module named 'serial'`** — выполнить `pip install pyserial`.
- **Порт не открывается / занят** — закрыть другие программы, работающие с этим
  COM-портом; проверить номер порта в Диспетчере устройств.
- **Нет ответа от прибора** — проверить, что TX↔RX перекрещены, общий GND,
  уровни 3.3 В, скорость 9600, и (по отчёту) вывод P1.0 в LOW при включении.
