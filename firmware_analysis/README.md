# Анализ и дизассемблирование прошивки MSP430 (`201.2_2.hex`)

Материал дипломной работы: разбор бинарной прошивки, полученной от
руководителя, её дизассемблирование, восстановление протокола обмена и
программа для общения с устройством по последовательному порту.

## Содержимое каталога

| Файл | Назначение |
|------|-----------|
| `firmware/201.2_2.hex` | исходная прошивка (Intel HEX) |
| `msp430dis.py` | дизассемблер MSP430 + загрузчик Intel HEX (написан для этой работы) |
| `disasm.lst` | результат дизассемблирования с комментариями и именами |
| `protocol.py` | библиотека и CLI для обмена с устройством по UART |
| `gui.py` | графический интерфейс (tkinter) поверх `protocol.py` |
| `README.md` | этот документ — полный разбор |

Команды воспроизведения:

```bash
python3 msp430dis.py firmware/201.2_2.hex --map        # карта памяти и векторы
python3 msp430dis.py firmware/201.2_2.hex --sfr        # использованные регистры
python3 msp430dis.py firmware/201.2_2.hex -o disasm.lst # полный листинг
python3 protocol.py --build --addr 04A2CB71 --cmd 0x40  # собрать кадр запроса
```

---

## 1. Формат файла

Файл — текстовый **Intel HEX** (записи `:LLAAAATT…CC`, CRLF-переводы строк).
Разбор (`load_ihex` в `msp430dis.py`): все контрольные суммы записей верны,
завершающая запись `:00000001FF` (EOF).

Занятые области памяти:

```
0x1000-0x10FF     256 байт   — информационная flash (сегменты A/B/C/D)
0x8000-0xFFFF   32768 байт   — основная flash (код + константы + векторы)
```

Такая карта (info-flash с 0x1000, вектора в 0xFFE0…0xFFFF, ОЗУ с 0x0200) —
однозначно **микроконтроллер Texas Instruments MSP430**. По используемой
периферии (FLL+, USART0, Basic Timer, вывод на 7-сегментный ЖКИ) это
семейство **MSP430F4xx**.

Реально непустых (≠ `0xFF`) байт — 7414; основной код расположен плотно в
диапазоне **0xE000–0xFCD3**.

---

## 2. Таблица векторов прерываний (0xFFE0–0xFFFF)

```
0xFFFE  RESET            -> 0xEE2E   главная точка входа
0xFFFC  NMI/OSC/FLASH    -> 0xEE2E
0xFFFA  Timer_B0         -> 0xF84A   обработчик Timer_B (динамическая индикация)
0xFFF4  WDT              -> 0xEE2E
0xFFF2  USART0 RX        -> 0xFC6A   приём байта по UART
0xFFF0  USART0 TX        -> 0xFCA0   передача байта по UART
0xFFE8  PORT1            -> 0xEE2E
0xFFEA  Timer_A1         -> 0xEE2E
0xFFE2  USART1 TX / BT   -> 0xF6F6   вспомогательный ввод (P2.0, программный)
0xFFE0  DAC/DMA / BT     -> 0xFB6C   Basic Timer: часы, тайм-ауты, индикация
```

Векторы, указывающие на `0xEE2E` (сам RESET) — это «ловушки»
неиспользуемых прерываний: любое такое прерывание перезапускает МК.

Ключевые для протокола: **USART0 RX (0xFC6A)**, **USART0 TX (0xFCA0)** и
**Basic Timer (0xFB6C)**.

---

## 3. Инициализация (RESET → 0xEE2E)

Порядок из `disasm.lst`:

1. `MOV #0x0300, SP` — установка вершины стека, `DINT`.
2. `init_clock_io` (0xEB7C):
   - `WDTCTL = 0x5A8D` — сторожевой таймер в интервальный режим;
   - настройка FLL+: `SCFQCTL = 0x7F` → DCO = (127+1)·32768 ≈ **4.194 МГц**,
     ожидание снятия флага DCOF;
   - настройка портов P1/P2 (светодиод/линия управления на P1, вход P2).
3. `init_vars` (0xEC02): очистка/инициализация ОЗУ, установка адреса
   устройства и паспортных значений, вызов `uart_enable`.
4. **Настройка USART0** (0xEC80, если разрешён приём — бит P1.0):
   ```
   U0BR0 = 0xB4, U0BR1 = 0x01   -> делитель = 0x01B4 = 436
   ME1  |= 0xC0                  -> включить приёмник и передатчик (URXE0|UTXE0)
   U0CTL = 0x11 -> 0x10          -> 8 бит, без чётности, 1 стоп; снять SWRST
   U0TCTL = 0x30                 -> тактирование от SMCLK
   P2SEL |= 0x30                 -> вывести RXD/TXD на выводы порта
   ```
   **Скорость:** SMCLK ≈ 4.194 МГц, делитель 436 → 4194304/436 ≈ **9615 бод**.
   Итог: **UART 9600 8N1**.
5. `EINT` — глобальное разрешение прерываний, вход в главный цикл.

---

## 4. Главный цикл (0xEF80 …)

Каждую итерацию:

- сброс сторожевого таймера (`WDTCTL = 0x5A0D`);
- мигание индикатором (`XOR.B #2, &P1OUT`);
- `display_update` (0xF98A) — обновление ЖКИ;
- `clk_advance` (0xFBFC) — доведение показаний часов (BCD-арифметика);
- `proto_service` (0xE000) и `proto_dispatch` (0xE404) — обработка принятого
  кадра, если он собран полностью (бит `0x0010` в слове состояния `status`).

Часы реального времени хранятся как BCD в ячейках `clk_hh/clk_mm/clk_ss`
(0x0208–0x020A) и продвигаются десятичным сложением (инструкции `DADD`) —
классическая программная реализация RTC на Basic Timer.

## 5. Приём/передача по UART

### Приём — ISR USART0 RX (0xFC6A)

```
очистить флаг URXIFG0
если кадр не в режиме передачи:
    если rx_ptr < 0x0246:          # защита от переполнения буфера
        frame_buf[rx_ptr++] = U0RXBUF
    иначе rx_ptr = frame_buf (сброс)
rx_timeout = 2                     # перезапуск тайм-аута паузы
```

### Завершение кадра — Basic Timer ISR (0xFB6C)

```
... (обслуживание светодиода, часов, динамической индикации) ...
если rx_timeout != 0:
    rx_timeout--                   # 2 «тика» тишины на линии
    если стало 0:
        status |= 0x0010           # признак «кадр принят полностью»
        frame_len = rx_ptr         # зафиксировать длину
```

То есть **граница кадра определяется по паузе на линии** (silent interval) —
как в Modbus RTU.

### Передача — ISR USART0 TX (0xFCA0)

Побайтно выдаёт `frame_buf[rx_ptr++]` в `U0TXBUF`, пока `rx_ptr < frame_len`;
затем снимает флаг активной передачи (`status.bit 0x4000`). Передача
запускается установкой этого флага и `IFG2 |= UTXIFG0`.

## 6. Формат кадра протокола

Восстановлен из разбора адреса (0xE43E) и минимальной длины (0xE40E):

```
+------+------+------+------+------+---------- ... ----------+--------+--------+
|  A0  |  A1  |  A2  |  A3  | CMD  |          DATA           | CRC_lo | CRC_hi |
+------+------+------+------+------+---------- ... ----------+--------+--------+
 \___________ адрес 4 б ____________/  1 б     0..N байт      Modbus CRC16
```

- **Адрес (4 байта)** сравнивается с адресом устройства из info-flash
  `0x1008…0x100B`. Значение по умолчанию в этой прошивке: **`04 A2 CB 71`**.
  Адрес `00 00 00 00` — **широковещательный** (устройство отвечает всем).
- **CMD** — байт команды: старший полубайт = группа (0x0…0x6),
  младший полубайт = индекс регистра в таблице этой группы.
- **CRC16** — стандартный **Modbus CRC16** (init `0xFFFF`, полином `0xA001`,
  отражённый), считается по всем предыдущим байтам и передаётся
  **младшим байтом вперёд**. Подпрограмма `crc16_modbus` (0xE5B8);
  эквивалентность эталону проверена численно (см. `protocol.py`, функция
  `crc16`).
- **Минимальная длина кадра — 7 байт** (4 + 1 + 2). Кадр короче
  отбрасывается (0xE40E: `CMP #0x023B, &frame_len; JL …`).

## 7. Диспетчер команд (таблица 0xE722)

`cmd_lookup` (0xE4A0) берёт байт `cmd_byte`, по старшему полубайту выбирает
запись в таблице по адресу **0xE722** (7 записей по 8 байт):

```
запись группы = { check_fn, count, reg_table_ptr, action_fn }
```

- `check_fn` — функция предварительной проверки (длина/разрешение линии);
- `count` — число доступных регистров в группе;
- `reg_table_ptr` — таблица дескрипторов регистров группы:
  каждый элемент = `{ ram_ptr (2 б), length (2 б) }`;
- `action_fn` — обработчик: **0xE536** — чтение (сборка ответа),
  **0xE600** — запись/программирование flash.

Расшифровка групп:

| Группа | check | action | Назначение |
|:------:|:-----:|:------:|------------|
| 0x0 | 0xE4D0 | 0xE600 | групповое чтение серийных данных / **запись во flash 0x1000** |
| 0x1 | 0xE4F6 | 0xE536 | чтение статуса / конфигурации |
| 0x2 | 0xE4F6 | 0xE536 | установка часов (RTC) |
| 0x3 | 0xE4F6 | 0xE536 | чтение часов (RTC) |
| 0x4 | 0xE51E | 0xE600 | чтение паспортных/калибровочных регистров |
| 0x5 | 0xE526 | 0xE536 | запись паспортных/калибровочных регистров |
| 0x6 | 0xE4F6 | 0xE536 | чтение счётчиков / буферов |

Пример таблицы регистров группы 0x4 (адрес 0xE782) —
пары `ram_ptr : length`:

```
[0] 0x1000 : 2    [1] 0x1002 : 4    [2] dummy : 0    [3] 0x0294 : 4
[4] dummy  : 1    [5] dummy : 0     [6] 0x1006 : 2   [7] 0x100C : 3
```

`dummy` (0x0255) — заглушка «регистр отсутствует».

Ячейка **0x0294** (`shadow_1000`) — теневая копия страницы info-flash
`0x1000`, через которую идёт безопасная перезапись сегмента (контроллер
flash: `FCTL1/2/3`, пароли `0xA5xx`, обработчик 0xE600).

## 8. Содержимое info-flash (0x1000)

```
0x1000: 77 58            паспортные данные (регистр 0x40[0])
0x1002: 52 27 8B 3F      паспортные данные (регистр 0x40[1])
0x1006: 00 00            флаги режима (регистр 0x40[6]) — 0x55 включает режимы
0x1008: 04 A2 CB 71      АДРЕС УСТРОЙСТВА (регистр 0x40[7]/0x53[3])
0x100C: 14 11 17         дата/версия (регистр 0x40[7])
0x1080: 03 02 00 05 04 10  конфигурационная запись (регистр 0x18)
```

Байт `0x1007` (`0x55`/`0xAA`) переключает режим динамической индикации —
проверяется в Basic Timer ISR (0xFBB2).

Таблица 7-сегментных кодов цифр 0–9 находится по адресу 0xE7D6:
`3F 06 5B 4F 66 6D 7D 07 7F 6F` — подтверждает наличие цифрового ЖКИ.

---

## 9. Карта ключевых ячеек ОЗУ

| Адрес | Имя | Назначение |
|-------|-----|-----------|
| 0x0208–0x020A | `clk_hh/mm/ss` | часы реального времени (BCD) |
| 0x0218 | `status` | слово флагов состояния (биты приёма/передачи, тайм-аутов) |
| 0x021A | `flags2` | флаги адресации (совпадение адреса, широковещание) |
| 0x022E | `rx_timeout` | счётчик паузы для детекции конца кадра |
| 0x0230 | `frame_len` | длина принятого кадра |
| 0x0232 | `rx_ptr` | текущий указатель в буфере |
| 0x0234 | `frame_buf` | буфер кадра (адрес занимает первые 4 байта) |
| 0x0238 | `cmd_byte` | байт команды кадра |
| 0x0239 | `resp_buf` | буфер формируемого ответа |
| 0x0294 | `shadow_1000` | теневая копия info-flash для перезаписи |

Биты слова `status` (0x0218), восстановленные по обращениям:
`0x0008` пришёл байт, `0x0010` кадр собран, `0x0020` ответ готов,
`0x0040` широковещательный кадр, `0x0400` запрос на сброс/реинициализацию,
`0x4000` идёт передача.

## 10. Программа для общения (`protocol.py`)

Реализует протокол из раздела 6: сборка кадра, расчёт/проверка Modbus CRC16,
обмен по последовательному порту (9600 8N1) с детекцией конца кадра по паузе.

Без оборудования (проверка формата и CRC):

```bash
$ python3 protocol.py --build --addr 04A2CB71 --cmd 0x40
Собранный кадр (7 байт):
  04 A2 CB 71 40 A2 26
  ...
  CRC расчёт  : 0x26A2  [OK]

$ python3 protocol.py --parse "04 A2 CB 71 40 A2 26"     # разобрать дамп
```

С реальным устройством (нужен `pip install pyserial`):

```bash
# прочитать паспортный регистр 0x40:
python3 protocol.py --port /dev/ttyUSB0 --addr 04A2CB71 --read 0x40
# прочитать часы (группа 0x3):
python3 protocol.py --port /dev/ttyUSB0 --addr 04A2CB71 --read 0x30
```

Из своего кода:

```python
from protocol import Device
dev = Device('/dev/ttyUSB0', addr='04A2CB71')
resp = dev.read_reg(0x40)        # чтение паспортных данных
print(resp['data'].hex(), 'CRC OK' if resp['crc_ok'] else 'CRC BAD')
dev.close()
```

### Графический интерфейс (`gui.py`)

Оконное приложение на **tkinter** (входит в стандартную библиотеку Python —
отдельная установка не нужна; на Linux при отсутствии: `sudo apt install
python3-tk`). Запуск:

```bash
python3 gui.py
```

Возможности:

- выбор COM-порта (с обновлением списка) и скорости, поле адреса устройства и
  кнопка «широковещательный»;
- готовые команды (чтение/запись RTC, паспортных данных, счётчиков) и
  ручной ввод байта команды и данных в HEX;
- кнопка «Отправить»: показывает собранный кадр, а при открытом порте —
  выполняет обмен в фоне (окно не «зависает») и разбирает ответ;
- журнал обмена с подсветкой: запрос (синий), ответ (зелёный), ошибки и
  неверный CRC (красный);
- **режим просмотра без оборудования**: если порт не открыт, приложение
  просто формирует и разбирает кадр — удобно для демонстрации протокола.

## 11. Итог

Прошивка — управляющая программа устройства на **MSP430F4xx** с
7-сегментным ЖКИ, программными часами реального времени и обменом по
**UART 9600 8N1**. Протокол — Modbus-подобный:
`[4-байтный адрес][команда][данные][Modbus CRC16]`, граница кадра — по паузе
на линии, команды сгруппированы через таблицу дескрипторов регистров с
возможностью чтения, записи и перепрошивки сегмента info-flash.

Восстановлены: карта памяти, таблица векторов, схема тактирования и UART,
формат кадра, алгоритм CRC (сверен с эталоном), таблица команд и регистров.
На основе этого написана рабочая программа обмена `protocol.py`.
