# Сборка exe под Windows

## Быстрый путь

1. Распакуйте архив в отдельную папку.
2. Положите туда `CH341DLLA64.dll` (для 64-битного Python) или `CH341DLL.dll`
   (для 32-битного). Файл идёт с драйверами программатора CH341 от WCH.
3. Запустите **`build_windows.bat`** двойным щелчком.

Готовый файл появится в `dist\CRC_Storage_Writer.exe`.

## Что делает .bat

| Шаг | Действие |
|---|---|
| 1 | Ищет Python (`py -3`, затем `python`), определяет разрядность |
| 2 | Проверяет, что все нужные файлы на месте |
| 3 | Ставит PyQt5, i2cpy, PyInstaller 6+ |
| 4 | Проверяет наличие DLL под вашу разрядность |
| 5 | Чистит прошлую сборку и компилирует по `crc_storage_writer.spec` |
| 6 | Проверяет, что exe создан, и печатает путь с размером |

На каждом шаге при ошибке сборка останавливается с внятным сообщением, а не
падает молча.

## Почему нужен .spec, а не голая команда

Обычная `pyinstaller crc_storage_gui.py` даёт exe, который **не сможет
писать в микросхему**. Две причины, обе закрыты в `crc_storage_writer.spec`:

### 1. Драйвер грузится динамически

i2cpy подбирает драйвер по строке:

```python
driver_module_name = "i2cpy.driver.{}".format(self.driver_name)
self.driver_module = import_module(driver_module_name)
```

Статический анализ такого не видит, модуль в сборку не попадает, и на
попытке открыть программатор вылетает `I2CInvalidDriverError`. Поэтому все
модули драйверов перечислены в `hiddenimports` явно.

### 2. DLL грузится по голому имени

```python
dll_name = "CH341DLLA64.dll" if sys.maxsize > 2147483647 else "CH341DLL.dll"
windll.LoadLibrary(dll_name)
```

Это происходит **прямо при импорте** драйвера. В onefile-сборке файлы
распаковываются во временную папку `sys._MEIPASS`, которой нет в путях
поиска DLL, — загрузка падает.

Решает runtime-хук `pyi_rth_ch341.py`: он выполняется до кода приложения,
находит DLL в `_MEIPASS` и подставляет переменную окружения `CH341DLL` с
полным путём. i2cpy читает её раньше, чем берёт имя по умолчанию:

```python
dll_name = os.getenv("CH341DLL")
```

Хук аккуратен: заданное вручную значение `CH341DLL` не перетирает, а если
DLL в сборку не клали — молча ничего не делает, и библиотека ищется рядом с
exe и в системе, как обычно.

## Если DLL нет на момент сборки

Сборка пройдёт, .bat об этом предупредит. Тогда положите `CH341DLLA64.dll`
рядом с готовым exe — этого достаточно.

## Ручная сборка

```cmd
pip install PyQt5 i2cpy "pyinstaller>=6.0"
pyinstaller --noconfirm --clean crc_storage_writer.spec
```

`spec` написан под PyInstaller 6+: в 5.x форма `EXE(...)` отличалась
(там был отдельный `a.zipfiles`).

## Проверка результата

Что должно быть внутри собранного exe:

- модули `i2cpy.driver.ch341`, `i2cpy.driver.ch341.dll`, `i2cpy.driver.ch347`
- модуль `crc_storage_i2c`
- runtime-хук `pyi_rth_ch341`
- сама `CH341DLLA64.dll`, если она была рядом при сборке

Сборка проверена на PyInstaller 6.22: все перечисленное попадает внутрь,
приложение стартует без ошибок импорта. Размер — около 48 МБ.

## Иконка

Положите `icon.ico` рядом со spec — она подхватится сама. Нет файла —
соберётся со стандартной иконкой.
