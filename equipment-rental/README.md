# СпецАренда — платформа аренды спецтехники

Маркетплейс для аренды спецтехники: арендаторы ищут и бронируют технику,
владельцы размещают объявления и получают оплату за вычетом комиссии
платформы, которая удерживается автоматически при каждой сделке.

## Стек

- **Next.js 16** (App Router, TypeScript, Tailwind CSS 4)
- **PostgreSQL** + **Drizzle ORM**
- **NextAuth v5** (email/пароль)
- **Stripe Connect** (Express-аккаунты) для выплат владельцам и
  автоматического удержания комиссии платформы

## Быстрый старт

### 1. База данных

Поднимите локальный PostgreSQL через Docker:

```bash
docker compose up -d
```

Или укажите `DATABASE_URL` на свою существующую базу в `.env`.

### 2. Переменные окружения

```bash
cp .env.example .env
```

Заполните `.env`:

- `DATABASE_URL` — строка подключения к PostgreSQL
- `AUTH_SECRET` — случайная строка (например, `openssl rand -base64 32`)
- `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` — тестовые ключи из
  [Stripe Dashboard](https://dashboard.stripe.com/test/apikeys)
- `PLATFORM_COMMISSION_PERCENT` — процент комиссии платформы (по умолчанию 10)

### 3. Установка зависимостей и миграции

```bash
npm install
npm run db:push   # применяет схему Drizzle к базе данных
npm run db:seed   # создаёт демо-категории и объявления
```

Демо-аккаунт владельца после сида: `demo-owner@example.com` / `password123`
(у него ещё не подключены выплаты Stripe — для тестирования оплаты подключите
Stripe Connect в личном кабинете любого зарегистрированного пользователя).

### 4. Запуск

```bash
npm run dev
```

Откройте http://localhost:3000

## Как устроена комиссия

1. Владелец подключает выплаты через Stripe Connect (`/dashboard/payouts`) —
   создаётся Express-аккаунт и проходит онбординг.
2. Арендатор выбирает даты и оплачивает аренду через Stripe Checkout.
3. Платёж проходит как **destination charge**: вся сумма списывается с
   арендатора, `application_fee_amount` (комиссия платформы) остаётся на
   основном Stripe-аккаунте платформы, остальное автоматически переводится
   на счёт владельца (`transfer_data.destination`).
4. Вебхук `checkout.session.completed` (`/api/stripe/webhook`) помечает
   бронирование как оплаченное.

Для локальной разработки перенаправляйте вебхуки Stripe через CLI:

```bash
stripe listen --forward-to localhost:3000/api/stripe/webhook
```

## Важные ограничения MVP

- **Stripe не работает с российскими юрлицами/RUB.** Цены в интерфейсе
  показаны в рублях для удобства, но реальный платёж проходит в валюте из
  `STRIPE_CURRENCY` (по умолчанию `usd`). Если владельцы техники и арендаторы
  находятся в России, для боевого запуска потребуется российский платёжный
  провайдер (ЮKassa, CloudPayments, Т-Банк Эквайринг и т.п.) с похожей схемой
  сплит-платежей/маркетплейса — компонент оплаты (`src/app/api/stripe/*`)
  нужно будет заменить на аналогичную интеграцию.
- Загрузка фото объявлений сохраняет файлы локально в `public/uploads` —
  подходит для разработки, для продакшена стоит подключить S3-совместимое
  хранилище или Cloudinary.
- Отмена уже оплаченного бронирования владельцем не оформляет автоматический
  возврат денег — возврат в MVP делается вручную через Stripe Dashboard.
- Бронирование работает по модели «мгновенное бронирование»: оплата
  происходит сразу после выбора дат, без отдельного шага подтверждения
  владельцем.

## Структура проекта

```
src/
  app/                 маршруты App Router (страницы + API)
  components/          переиспользуемые UI-компоненты
  db/                  схема Drizzle, клиент БД, сид-скрипт
  lib/                 auth, stripe, валидация (zod), утилиты
```
