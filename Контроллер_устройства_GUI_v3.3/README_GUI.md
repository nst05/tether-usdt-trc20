# Контроллер устройства — GUI (оптический/последовательный порт), v3.3 Physical

Программа управления **устройством** по физическому оптическому/последовательному
порту (USB-оптоголовка, UART 9600 8N1). Позволяет читать и задавать параметры,
выполнять сервисные действия, снимать телеметрию и вести журнал сессии. Компоновка
окна, вкладки и каталог 158 команд сохранены. Эмулятор устройства и демонстрационный
режим удалены — обмен идёт только с реальным портом.

## Полное управление: вкладка «Панели управления» (v3.3)

Вкладка **«Панели управления»** даёт доступ ко **всем 158 командам**, разложенным по
функциональным группам (накопители, датчик и температура, фильтр Калмана, актуатор,
связь GSM/RS-485/сервер, дисплей/сервис/питание, защита от вмешательства,
доступ/пароли, служебное). У каждой команды в строке:

- **Get** — прочитать текущее значение;
- поле значения (для параметров) или пресет-список для флагов/enum;
- **Set** — записать значение / **Действие** — выполнить (для команд-действий).

Кнопка **«Прочитать группу»** снимает все параметры группы за раз и заполняет поля.

### Полный снимок прибора и профиль

- **«Прочитать ВСЁ (158)»** (вкладка «Команды» → Быстрые действия, либо «Панели
  управления») — читает все параметры прибора одним действием.
- **«Профиль устройства → файл…»** — сохраняет снятый снимок в **JSON** или **CSV**
  (имя команды, группа, тип, значение) для отчёта/дипломной работы.

Снимок читает **только параметры-значения**. Команды-**действия**
(`VALVE_TRY_CLOSE`, `CLEAR_SABOTAG`, `RSTSMT` и т. п.) в полное/групповое чтение
**не включаются**: их «голое» имя на реальном приборе выполнило бы операцию, а не
вернуло значение. Действия выполняются только явной кнопкой «Действие» в экспертном
режиме. Изменение критичных параметров по-прежнему требует **экспертного режима** —
предохранитель v3.2 сохранён полностью.

## Журнал сессии (вся работа с прибором сохраняется)

Каждый обмен по оптопорту — чтение, запись, действие, аутентификация — **сразу пишется на диск** в папку `sessions/`:

- `sessions/optic_<штамп>.jsonl` — по одной JSON-записи на обмен (время, команда, TX/RX в hex, значение, задержка, число попыток, снятие эха, флаги критичности/эксперта);
- `sessions/optic_<штамп>.log` — человекочитаемый протокол.

Файл заводится при подключении и переживает перезапуск (каждый запуск — свой файл). **Секреты (пароли, `MAGIC`, `APN_PASSWORD`) в журнал не пишутся — значение маскируется `•••`.**

Меню **«Сессия»**: «Экспорт сессии в CSV…» и «Открыть папку sessions». Офлайн-конвертация ранее снятого журнала:

```bash
python3 smt_session.py sessions/optic_20260722_101500.jsonl отчёт.csv
```

## Расширенный список критичных команд (v3.2)

Экспертный режим теперь требуется не только для очевидных записей, но и для: перенаправления телеметрии (`SERVER_URL`, `SERVER_URL2`, `APN_*`), сброса тревог (`WARNING_CLEAR`, `ALARM_CLEAR`, `CRASH_CLEAR`), часов (`DATETIME`, `RTC_CALIB`). При этом **чтение** любого из этих параметров (get) по-прежнему свободно — блокируется только изменение. Второй рубеж защиты продублирован в `smt_client.SmtClient.send` (пропускает запись/действие только с `expert=True`).

## Что исправлено

- Подключение считается успешным только после фактического ответа `DevInfo`.
- Автоопределение кадрирования выполняется безопасной командой чтения, а не текущей командой пользователя.
- Команды записи и действия никогда не повторяются автоматически.
- Команды чтения повторяются один раз при потере ответа.
- Снимается само-эхо USB-оптоголовки; в hex-журнале сохраняются исходные байты линии.
- Ответ собирается до межбайтовой паузы, поэтому корректно обрабатываются фрагменты UART.
- Обрабатываются отключение USB, занятый порт, таймаут записи и потеря связи.
- Порт, baud и режим кадрирования запоминаются между запусками.
- TCP-пакеты физического прибора автоматически сохраняются в `sessions/*.log` и `sessions/*.json`.
- Критические записи по-прежнему доступны через существующий экспертный режим GUI и отправляются ровно один раз.

## Обезличенные имена команд (CMD_###)

В интерфейсе и логах команды показываются как `CMD_000…CMD_157` (модуль
`smt_aliases.py`). Реальное имя команды подставляется автоматически **только на
провод** — в единственной точке `SmtClient.send`, поэтому проверки безопасности
(гейт критичных, PROTECTED_WRITE) и то, что уходит в устройство, всегда работают с
настоящим именем. Соответствие CMD_### ↔ реальное имя строится из порядка команд в
`smt_commands.json`. В «Свободной команде» можно вводить как `CMD_045`, так и
реальное имя — обе формы уходят корректно.

## Установка

### Windows

1. Установить Python 3 с компонентом Tcl/Tk.
2. Открыть PowerShell или CMD в папке проекта.
3. Выполнить:

```bat
py -3 -m pip install -r requirements.txt
py -3 smt_gui.py
```

Можно использовать `start_gui.bat`.

### Linux

```bash
sudo apt install python3 python3-tk python3-pip
python3 -m pip install -r requirements.txt
python3 smt_gui.py
```

Если нет доступа к `/dev/ttyUSB*`:

```bash
sudo usermod -aG dialout "$USER"
```

После изменения группы нужно заново войти в систему.

## Первый запуск с прибором

1. Подключить USB-оптоголовку и убедиться, что она появилась как `COMx`, `/dev/ttyUSBx` или `/dev/ttyACMx`.
2. В GUI нажать **«Порты…»**. Если найден ровно один подходящий порт, он подставится автоматически.
3. Оставить `9600`, `8N1` и кадр `auto`, если прошивка не настроена иначе.
4. Нажать **«Подключить»**.
5. GUI переберёт `cr`, `crlf`, `brace`, `iec` только командой `DevInfo`.
6. Зелёный статус появится только после ответа вида `DevInfo=...;`.
7. Нажать **«Пре-флайт»**, затем прочитать `DEVICE_SN`, `VER_PO`, `STATUS_SYSTEM`.

При успешном обмене вкладка **«Сырые байты (hex)»** показывает точный запрос и точный ответ на проводе.

## Диагностика без GUI

```bash
python3 optic_preflight.py COM4
python3 optic_preflight.py COM4 --baud 9600
python3 optic_preflight.py COM4 --framing crlf
python3 optic_preflight.py COM4 --probe DEVICE_SN
```

Linux:

```bash
python3 optic_preflight.py /dev/ttyUSB0
```

Проверка выводит:

- рабочее кадрирование;
- задержку ответа;
- наличие само-эха;
- фактические TX/RX-байты;
- значение `DevInfo`.

## Настройка таймаутов для незавершённой прошивки

По умолчанию GUI ждёт первый ответ до 2,5 секунды, завершает пакет после паузы 250 мс и повторяет безопасное чтение один раз. Значения можно менять без переделки интерфейса:

### Windows CMD

```bat
set SMT_RESPONSE_TIMEOUT=5
set SMT_IDLE_GAP=0.5
set SMT_READ_RETRIES=2
py -3 smt_gui.py
```

### Linux

```bash
SMT_RESPONSE_TIMEOUT=5 SMT_IDLE_GAP=0.5 SMT_READ_RETRIES=2 python3 smt_gui.py
```

Записи и действия не повторяются независимо от `SMT_READ_RETRIES`.

## Экспертный режим

Интерфейс и поведение v3 сохранены:

- без экспертного режима критическая запись блокируется в GUI;
- после подтверждения команда отправляется физическому прибору;
- окончательное решение принимает прошивка согласно текущему уровню доступа;
- команда отправляется один раз, чтобы не повторить срабатывание при потерянном ответе.

Перед записью рекомендуется прочитать текущее значение и сохранить журнал сессии.

## Телеметрия физического прибора

Во вкладке **«Телеметрия»**:

1. Указать TCP-порт и нажать **«Слушать»**.
2. Настроить `SERVER_URL` прибора на IP компьютера и этот порт.
3. Дождаться соединения GPRS/TCP.
4. GUI сохранит исходный пакет и JSON-разбор в папку `sessions`.
5. Прибор получит `DATA ACCEPT:N`, где `N` — число распознанных записей.

Для отдельного серверного процесса:

```bash
python3 smt_server.py --host 0.0.0.0 --port 40000 --crc-scan
```

## Кнопка «Открыть дамп…»

Она сохранена, чтобы не менять интерфейс. Теперь кнопка **не подключает виртуальное устройство**. Она только загружает реальный `.bin`, снятый с физической flash-памяти, во вкладку «История».

## Если ответа нет

Проверять по порядку:

1. Порт существует и не занят терминалом/IDE/другим экземпляром GUI.
2. USB-UART имеет нужный логический уровень и общий GND с оптической схемой.
3. TX и RX не перепутаны; оптический передатчик и приёмник ориентированы правильно.
4. Оптопорт прошивки включён и не уснул по таймеру.
5. Baud совпадает с прошивкой.
6. В ручном режиме проверить `cr`, затем `crlf`, `brace`, `iec`.
7. Посмотреть hex: только повтор TX без ответа означает само-эхо без ответа прибора.
8. Увеличить `SMT_RESPONSE_TIMEOUT` и `SMT_IDLE_GAP` на этапе отладки прошивки.

Фактическая проверка электрических уровней и временных диаграмм выполняется осциллографом или логическим анализатором; GUI не может определить неправильное напряжение линии программно.
