# Форматы хранения данных прибора — подробный разбор (для защиты)

> Авторизованный аудит прошивки прибора обработки среды (STM32L433VCT6 + внешняя
> флеш-память W25Q64V, 8 МБ SPI). Документ описывает **где** и **в каком формате**
> прибор хранит показания, историю и журнал аудита, какие используются контрольные
> суммы, и **почему целостность этих данных не обеспечена криптографически**
> (находка для отчёта). Все адреса и раскладки подтверждены на реальном дампе;
> инструмент разбора — вкладка «История» в GUI и `smt_state.py` / `smt_eventlog.py`.

---

## 1. Карта памяти (где что лежит)

| Носитель | Регион | Назначение |
|---|---|---|
| **STM32 внутр. flash** | `0x08000000` | загрузчик |
| | `0x08004000` | приложение (образ прошивки) |
| | `0x0801D9C4` | таблица-дескриптор инициализации (пары «источник→приёмник») |
| | `0x080337E0…` | образ конфигурации по умолчанию (строки паролей, APN, USSD) |
| **STM32 SRAM (ОЗУ)** | `0x20000278` | **мастер-структура конфигурации** (рантайм) |
| | `0x20000D62` | байт текущего уровня доступа (`f`/`U`/0) |
| **W25Q64 SPI (8 МБ)** | `0x000000…0x128000` | **главный архив** показаний |
| | `0x15E000…0x171000` | **журнал событий / аудита** |
| | `0x7FC000` и `0x7FE000` | **чекпоинт состояния** (две половины, пинг-понг) |
| | `0x780000…` | зеркало образа прошивки |

## 2. Чекпоинт состояния (показания) — `0x7FE000` / `0x7FC000`

**Механизм.** Две половины по **8 КБ** в самом верху флеш-памяти работают по схеме
**пинг-понг**: прибор пишет по очереди то в одну, то в другую (износ-выравнивание и
защита от сбоя питания). **Активна** та половина, у которой первые 4 байта первой
записи **≠ `0xFFFFFFFF`**. Внутри половины — **кольцо из 64 записей по 128 байт**
(`0x2000 / 0x80 = 64`); каждая запись — **почасовой снимок** прибора. Пустой слот
кольца = `0xFFFFFFFF` в начале.

**Раскладка записи (128 Б), подтверждена на дампе:**

| Смещение | Тип | Поле | Комментарий |
|---|---|---|---|
| `+0x00` | float64 | **показания** (накопленный объём, м³) | то, что на экране |
| `+0x08` | float64 | второй накопитель | реверс/резерв |
| `+0x10` | float64 | **копия показаний** | контроль целостности (см. §6) |
| `+0x18` | float32 | температура №1 (среды), °C | |
| `+0x20` | float32 | температура №2 (среды), °C | |
| `+0x24/+0x28/+0x2C` | float32 ×3 | каналы давления | `−35.0` = «не настроено» |
| `+0x38` | u32 | слово статуса/режима | |
| `+0x40` | u32 | порядковый номер записи | индекс в кольце |
| `+0x5C` | u32 | **маркер валидности** | старшие 16 бит = `0xA5A5` |
| `+0x60` | float32 | поправочный коэффициент | |
| `+0x74` | u32 | **метка времени Unix** | кратна часу |

**Проверка «валидности» записи (как её делает прибор и наш разбор):**
запись считается достоверной, если `(marker>>16)==0xA5A5` **И** `показания(+0x00)`
совпадают с `копией(+0x10)`. Это **единственная** защита — обычное дублирование
значения, не подпись (см. §6).

## 3. Главный архив показаний — `0x000000…0x128000`

Тот же тип записи (128 Б), но с **вынесенным вперёд заголовком**:

| Смещение | Тип | Поле |
|---|---|---|
| `+0x00` | u32 | метка времени Unix |
| `+0x08` | u32 | индекс записи |
| `+0x0C` | float64 | показания (накопленный объём) |
| `+0x1C` | float64 | копия показаний |
| `+0x24` | float32 | температура №1 |
| `+0x2C` | float32 | температура №2 |

Слот пуст, если время `= 0xFFFFFFFF`; «битым» считается время вне диапазона
`1e9…2e9` (2001…2033). Разбор — `smt_state.py --archive`.

---

## 4. Журнал событий / аудита — `0x15E000…0x171000`

**Назначение.** Аудит-трейл изменений конфигурации: **каждая правка настроек и ввод
в эксплуатацию** фиксируются как отдельное событие. По журналу восстанавливается
хронология: когда сброшены заводские, когда введён пароль, когда менялись пороги.

**Формат записи (шаг 16 Б):**

| Смещение | Тип | Поле |
|---|---|---|
| `+0x00` | u32 | метка времени Unix |
| `+0x08` | u32 | порядковый номер события |
| `+0x0C` | u16 | **код параметра/события** |
| `+0x0E` | ASCII, null-terminated | значение (текст) |

Запись считается валидной, если время в диапазоне `0x66000000…0x69800000`
(≈2024…2026) и регистр `< 100000`.

**Коды событий (расшифровка по значению/корреляции):**

| Код | Что фиксирует |
|---|---|
| `0x0205` | дата/время (`DATETIME`) |
| `0x02C6` | дата ввода в работу / калибровки |
| `0x020F` | **пароль провайдера** (⚠ пишется открытым текстом — F7) |
| `0x0220`, `0x02B7` | пароль OMEGA (маскированный) |
| `0x020B` | расписание передачи |
| `0x0278` | 6 калибровочных коэффициентов |
| `0x0233` | строка калибровочной таблицы (LUT) |
| `0x026D` / `0x026E` | температурный порог мин / макс |
| `0x0248` / `0x0249` | предел потока Q |
| `0x023C`, `0x026B` | **байт уровня доступа** (`f`=провайдер, `U`=omega) |
| `0x02D1` | сброс к заводским |

**Текстовые метки:** `DEF->RAM` — загрузка заводских настроек в ОЗУ (сброс/старт);
`RAM->USER` — фиксация настроек в пользовательский профиль.

> **⚠ Находка F7 в журнале.** Среди записей встречается пароль провайдера
> **открытым текстом** (`code 0x020F`, значение `123456`) — секрет попадает в
> энергонезависимый аудит-трейл.

## 5. Контрольные суммы и «крипто» (что реально применяется)

| Механизм | Где | Параметры |
|---|---|---|
| **CRC32** | аппаратный блок STM32 `0x40023000` | poly `0x04C11DB7`, init `0xFFFFFFFF`, без реверса вход/выход, без финального XOR = **CRC‑32/MPEG‑2** *(реверс-биты уточняются реальным пакетом)* |
| **CRC16 ×3** | заголовок телеметрии `%04X;%04X;%04X` | по секциям пакета; кандидаты параметров — XMODEM / KERMIT / MODBUS (определяются CRC16-сканом по реальному кадру) |
| **MD5** | `sub_08031DFC`/`sub_080324D0` | поле `auth=` телеметрии = MD5 по содержимому пакета |

Ключевой вывод: **все три механизма — это контроль ЦЕЛОСТНОСТИ (обнаружение
случайной порчи), а не ПОДПИСЬ.** CRC/MD5 без секретного ключа **пересчитываются
кем угодно**, кто имеет данные. Ни архив, ни чекпоинт, ни журнал не защищены
криптоподписью на уникальном ключе прибора.

## 6. Анализ целостности — почему данные изменяемы (находка)

**Что защищает записи сегодня:**
- чекпоинт: маркер `0xA5A5` + **дублирование** показания (`+0x00` vs `+0x10`);
- телеметрия: CRC16 ×3 + `auth=MD5(содержимое)`;
- журнал: **ничего** (простая последовательность записей).

**Почему это не защита от подделки:**
1. Дублирование показания — это защита от *битой ячейки*, а не от намеренной
   правки: изменивший `+0x00` просто впишет то же значение в `+0x10`.
2. CRC16/CRC32/MD5 — **бесключевые**: пересчитываются по открытым данным, поэтому
   после правки данных корректная контрольная сумма ставится тривиально.
3. Журнал аудита не подписан и не сцеплён (нет hash-chain), поэтому запись можно
   заменить/удалить, не оставив криптографического следа.

**Вывод для отчёта (класс F5/F6/F7).** Целостность показаний, истории и
аудит-журнала **на уровне хранения не обеспечена**: при доступе к памяти (SWD/flash;
RDP отключён — находка F1) данные можно изменить в обход контроля, а контрольные
суммы восстановить. Демонстрируется **чтением** (вкладка «История»): для записи с
рассинхроном `+0x00`/`+0x10` разбор показывает «Целостн. = НЕТ», но прибор всё равно
доверяет значению — сигнатуры, которая бы это поймала, нет.

**Рекомендация.**
- Подпись показаний, архива и **каждой записи журнала** через **HMAC-SHA256** на
  уникальном для прибора ключе; для журнала — **сцепление хешей** (hash-chain),
  чтобы удаление/подмена записи ломали цепочку.
- Хранение ключа и критичных регистров в **защищённом элементе** (secure element),
  а не в общей SPI-флеш.
- Включить **RDP уровня 2** (закрыть SWD-чтение памяти).
- Убрать запись секретов (паролей) в журнал открытым текстом.

## 7. Как проверить самому (воспроизводимость)

```
# история показаний (активная половина чекпоинта)
python3 smt_state.py <dump.bin>
# главный архив показаний
python3 smt_state.py <dump.bin> --archive
# журнал событий/аудита (вся хронология)
python3 smt_eventlog.py <dump.bin> --all
```
Или в GUI: вкладка **«История» → «Загрузить дамп…»** — таблицы чекпоинта и журнала,
столбец «Целостн.» демонстрирует §6.

> **Граница работы.** Инструмент **только читает и разбирает** хранилища. Средства
> изменения показаний/архива/журнала намеренно **не создавались**: цель аудита —
> доказать уязвимость и дать рекомендацию, а не предоставить средство подделки.
