Контроллер устройства — GUI (оптический/последовательный порт) v3.3 Physical

Основа: v3.2 Physical (только физический прибор, без эмулятора/демо).
Назначение: полное управление устройством по физическому оптическому/
последовательному порту (чтение/запись/действия, калибровка, журналы, телеметрия).

Изменения v3.3 (полное управление):
- новая вкладка «Панели управления»: ВСЕ 158 команд разложены по функциональным
  группам (накопители, датчик/температура, фильтр Калмана, актуатор, связь/сервер,
  дисплей/сервис/питание, защита от вмешательства, доступ/пароли); у каждой команды
  строка Get / Set / Действие и кнопка «Прочитать группу»;
- «Прочитать ВСЁ (158)»: полный снимок прибора одним действием;
- «Профиль устройства → файл…»: экспорт снятого снимка в JSON или CSV
  (имя, группа, тип, значение);
- полный/групповой снимок читает ТОЛЬКО параметры-значения; команды-ДЕЙСТВИЯ
  (VALVE_TRY_CLOSE, CLEAR_SABOTAG, RSTSMT и др.) в снимок не включаются — их
  «голое» имя выполнило бы операцию на приборе (безопасность снимка);
- экспертный режим и оба рубежа защиты критичных записей/действий сохранены без
  изменений: снятие показаний свободно, изменение критичных параметров — только
  осознанно в экспертном режиме;
- добавлены тесты (tests/test_physical.py): полнота снимка, исключение действий из
  чтения, групповое чтение — итого 13/13.

Изменения v3.2 (доработка):
- журнал сессии на диск: каждый обмен (чтение/запись/действие/аутентификация)
  сразу пишется в sessions/optic_<штамп>.jsonl и .log; переживает перезапуск;
- меню «Сессия»: экспорт журнала в CSV и открытие папки sessions;
- офлайн-конвертер: python3 smt_session.py <сессия.jsonl> [выход.csv];
- секреты (пароли/креды) в журнал не пишутся — значение маскируется (•••);
- список критичных на запись расширен (телеметрия SERVER_URL/APN,
  сброс тревог WARNING/ALARM/CRASH_CLEAR, часы RTC_CALIB/DATETIME и др.);
- второй рубеж защиты в smt_client.SmtClient.send стал «живым»: запись/действие
  проходит только с expert=True, но ЧТЕНИЕ защищённого параметра (get) разрешено;
- запись/действие по-прежнему не повторяются; чтение — с ограниченным повтором;
- критичные ДЕЙСТВИЯ (VALVE_TRY_CLOSE, CLEAR_SABOTAG и др.) теперь всегда
  классифицируются как действие (явный список в smt_client.IMPERATIVE_ACTIONS),
  а не как чтение из-за опечаток каталога: блокируются без эксперта, выполняются
  в экспертном режиме, без автоповтора;
- каталог smt_commands.json синхронизирован с реальным списком критичных команд;
- добавлены тесты без железа (tests/test_physical.py): кадрирование, эхо,
  сборка фрагментов, политика повторов, гейт критичных, журнал+маскирование.

Проверено без прибора:
- синтаксис и импорт всех модулей; 9/9 тестов tests/test_physical.py;
- инъекция FakeSerial (кадрирование, эхо, фрагментация, повторы, гейт);
- журнал сессии: запись, маскирование секретов, экспорт CSV.

Не заявляется:
- проверка на конкретной электрической схеме пользователя;
- подтверждение точных ответов незавершённой прошивки без физического захвата TX/RX.
