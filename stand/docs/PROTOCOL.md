# Протокол обмена со стендом — реконструкция по прошивке

Всё ниже выведено из дизассемблированной прошивки `stand/firmware.hex`.
Адреса в скобках — адреса во flash, по которым можно перепроверить утверждение
в `stand/dis.txt`.

## 1. Аппаратная платформа

| Свойство | Значение | Откуда |
|---|---|---|
| Ядро | MSP430 (семейство 2xx) | набор инструкций, `BCSCTL3`@0x53, `UC1IE`@0x06 |
| Flash | 0x1100–0xFFFF (60 КБ) | диапазон записей Intel HEX |
| INFO-память | 0x1000–0x10FF | отдельный блок в HEX |
| RAM | 0x0200–0x09FF (2 КБ) | `mov #0x0A00, SP` (0x1100) |
| MCLK / SMCLK | XT2 = **12 МГц** | `BCSCTL2 = 0x88` → SELM_2\|SELS (0x2552) |
| ACLK | LFXT1 = **32768 Гц** | `TBCCR0 = 0x8000` при TBSSEL_1 (0x1152) |
| Периферия | 2×USCI (A0/B0, A1/B1), Timer_A3, Timer_B7, ADC12, аппаратный умножитель, Comparator_A+, порты P1–P6 | по обращениям к регистрам |

Профиль (60 КБ flash + 2 КБ RAM + 2×USCI + Timer_B7 + ADC12) соответствует
**MSP430F249** и совместимым.

## 2. Физический уровень

Два **независимых и функционально идентичных** UART-канала:

| | Канал A1 | Канал A0 |
|---|---|---|
| Модуль | USCI_A1 | USCI_A0 |
| Буфер кадра | 0x04B0…0x04C7 (**24 байта**) | 0x0810…0x0827 (**24 байта**) |
| Указатель | 0x04A4 | 0x0828 |
| Счётчик | 0x04A6 | 0x082A |
| Флаги | 0x04A7 | 0x082B |
| Инициализация | `sub_4802` | `sub_48C0` |

Канал A1 дополнительно умеет работать **программным UART** на Timer_A
(ISR 0x2DC6): период бита 625 тактов SMCLK → 19200 бод, вывод через `TACCTL2`
в режиме OUTMOD_3. Используется как альтернативный физический интерфейс
(оптопорт / токовая петля) на том же логическом канале.

### Скорость и формат

Байт конфигурации — **RAM 0x04E0**:

| Биты | Смысл |
|---|---|
| 3:0 | индекс скорости, **должен быть < 6** (0x4828) |
| 5:4 | чётность: `0`=нет, `1`=нечётная, `2`/`3`=чётная (0x4916) |
| 7 | доп. режим — взводит бит 0x40 в флагах канала (0x48FE) |

Делители из таблиц flash 0xFB18 (`UCxBR0`) и 0xFB1E (`UCxBR1`); при SMCLK = 12 МГц:

| Индекс | Делитель | Скорость | Тайм-аут (0xFB24) |
|---|---|---|---|
| 0 | 625 | **19200** | 5 |
| 1 | 1250 | **9600** | 10 |
| 2 | 2500 | **4800** | 20 |
| 3 | 5000 | **2400** | 40 |
| 4 | 10000 | **1200** | 80 |
| 5 | 20000 | **600** | 160 |

**По умолчанию** (аварийная ветка 0x4936): делитель 0x09C4 = 2500 → **4800 бод,
8-O-1** (`UCAxCTL0 = 0x80` — UCPEN, нечётная), тайм-аут 20.

Формат данных всегда 8 бит, 1 стоп-бит, LSB первым; меняется только чётность.

## 3. Формат кадра

```
запрос:  [ADDR] [CMD] [ARG...]          [CRC_lo] [CRC_hi]
ответ:   [ADDR] [DATA...]               [CRC_lo] [CRC_hi]
```

* `ADDR` — сетевой адрес узла, хранится в **RAM 0x04FE**.
  Принимаются (0x833A): `0x00` (широковещательный), собственный адрес,
  `0xFE` (сервисный — только для `CMD=3` с подкомандами 8/0x0C/0x0D и для `CMD=7`).
  На кадр с адресом `0xFE` ответ **не передаётся** (0xB862).
* Максимальная длина кадра — **24 байта** (размер буфера). Длинные ответы
  передаются фрагментами с переносом состояния CRC (0x05A4 / 0x0830).

### CRC

`sub_BC22` — табличный расчёт по двум массивам flash: 0xFB3C (старшие байты)
и 0xFC3C (младшие). Аккумулятор в регистре хранится **побайтно переставленным**,
но алгоритм эквивалентен стандартному:

> **CRC-16/MODBUS** — полином 0xA001 (reflected), начальное значение 0xFFFF,
> без финального XOR.

Проверено: контрольный вектор `"123456789"` → **0x4B37**.

В кадр CRC дописывается **младшим байтом вперёд** (0xB894–0xB8A9), то есть
ровно как в Modbus RTU. CRC считается по всем байтам кадра до самого CRC.

## 4. Набор команд

Диспетчер: `sub_823E` → проверка адреса → проверка CRC → таблица переходов
**0x8474**, шаг 4 байта, допустимы **CMD 0…8** (0x8434).

| CMD | Обработчик | Длина запроса | Назначение |
|---|---|---|---|
| 0x00 | 0x8498 | 4 | тест канала связи |
| 0x01 | 0x84F4 | 11 | открытие канала: `[уровень][пароль×6]` |
| 0x02 | 0x8590 | 4 | закрытие канала |
| 0x03 | 0x85B2 | перем. | запись параметров, **56 подкоманд** (табл. 0x85D8) |
| 0x04 | 0xA0FE | перем. | запись (расширенная) |
| 0x05 | 0xA3B6 | 6 | чтение массивов, **7 подкоманд** (табл. 0xA432) |
| 0x06 | 0xA7C6 | перем. | **5 подкоманд** (табл. 0xA84A) |
| 0x07 | 0xAAEC | перем. | чтение вспомогательных, **3 подкоманды** (табл. 0xAB2E) |
| 0x08 | 0xAD98 | 5 или 6 | чтение параметров, **42 подкоманды** (табл. 0xAE18) |

`CMD=1` принимает уровень доступа **1 или 2** (0x84FA/0x8500) и сравнивает
6-байтный пароль (`sub_CC18`) с записью по смещению 0x4F (уровень 1) либо
0x48 (уровень 2).

Подкоманда — байт 2 кадра, маскируется до 6 бит и сохраняется в 0x07DF
(0x843E), плюс бит 0x40 при `CMD=3` и 0x80 при `CMD=7`.

### Ответ-квитанция

`sub_B842` формирует короткий ответ `[ADDR][CODE][CRC_lo][CRC_hi]`:

| CODE | Смысл | Адрес |
|---|---|---|
| 0x00 | успех | 0x84EC (`clr.b 1(r7)`) |
| 0x01 | неверная команда/параметр | 0xB842 |
| 0x02 | внутренняя ошибка | 0xB848 |

Бит 0x80 в байте кода взводится при активном режиме 0x40 канала (0xB88E).

### Реализованные подкоманды

* **CMD 0x03** (запись): реализована 41 из 56; не поддержаны
  3, 6, 7, 9, 11, 14, 15, 18, 19, 26, 28, 29, 30, 37, 38.
* **CMD 0x05**: реализованы все 7 (0…6).
* **CMD 0x06**: реализованы 1…4, подкоманда 0 — нет.
* **CMD 0x07**: реализованы 1 и 2, подкоманда 0 — нет.
* **CMD 0x08** (чтение): реализована 31 из 42; не поддержаны
  6, 8, 14, 15, 16, 21, 34, 35, 36, 37, 40.

Полная карта «подкоманда → адрес обработчика» — в `stand/meta.json`
(ключ `jumptables`).

Разобранные подкоманды `CMD=0x08`:

| Подкоманда | Обработчик | Содержание |
|---|---|---|
| 0x00 | 0xAEC0 | серийный номер (4 байта) + дата выпуска (3 байта), читается из INFO-памяти 0x1080 |
| 0x04 / 0x05 | 0xAF60 | сетевой адрес узла (0x04FE, либо 0x04E1 для второго канала) |
| 0x09 | 0xAFC2 | слово состояния из 0x04F4/0x04F5 |

Длина запроса `CMD=0x08` — **6 байт** для подкоманд
0x0C, 0x0D, 0x11, 0x14, 0x16, 0x1A, 0x27 (есть дополнительный параметр)
и **5 байт** для остальных (0xADAE–0xADF0).

## 5. Идентификация конкретного экземпляра

## 6. Эталонные кадры

```
тест связи, широковещательный   00 00 01 B0
тест связи, адрес 0x2A          2A 00 1E D0
открытие канала, ур.1, пароль 111111
                                2A 01 01 01 01 01 01 01 01 90 E0
закрытие канала                 2A 02 9F 11
чтение SN и даты (08/00)        2A 08 00 57 C8
чтение сетевого адреса (08/05)  2A 08 05 97 CB

ответ «успех»                   2A 00 1E D0
ответ «неверная команда»        2A 01 DF 10
```

## 7. Что осталось непокрытым

Рекурсивный обход достигает 51 544 байт из 60 928 (85 %). Непокрытое —
это таблицы констант (в т. ч. две таблицы CRC по 256 байт, таблицы скоростей)
и ветки, достижимые только через косвенные вызовы через указатель в регистре.
Семантика отдельных подкоманд `CMD=0x03`/`0x04`/`0x05` разобрана не до конца —
это следующий шаг, когда будет ясно, какие функции нужно добавлять.
