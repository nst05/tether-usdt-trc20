# Контроллер устройства 4.1 HARDWARE MAX

Программа предназначена для работы **с реальным прибором**. Виртуальных устройств и подмены ответов в проекте нет. Каталог содержит **158 команд** прошивки: чтение параметров, разрешённая уровнем доступа запись, сервисные действия, работа с актуатором, связью, архивами, телеметрией и диагностикой.

## Реальные каналы связи

### USB-оптопорт / Serial

Поддерживаются:

- произвольный COM/tty-порт и скорость от 300 до 230400 бод;
- 5/6/7/8 бит данных, чётность N/E/O/M/S, 1/1.5/2 стоп-бита;
- XON/XOFF, RTS/CTS, DSR/DTR и явные уровни DTR/RTS;
- кадрирование `cr`, `crlf`, `brace`, `iec` или автоматическое определение по `DevInfo`;
- настройка таймаута ответа, межбайтовой паузы и повторов безопасного чтения;
- автоматическое удаление точного оптического эха из разбираемого ответа;
- сохранение реальных TX/RX-байтов и задержки каждого обмена.

### TCP-шлюз

Командный request/response через реальный TCP-шлюз: host, port, таймаут и окончание команды `нет/CR/LF/CRLF`. Каталог, экспертный режим, журналирование, сценарии, снимки и мониторинг работают так же, как через оптопорт.

### GSM / SMS

Работа через физический GSM-модем с AT-интерфейсом:

- отправка команд SMS;
- собственный префикс команды;
- чтение непрочитанных SMS и опциональное удаление;
- ручные AT-команды, например `AT+CSQ`, `AT+CREG?`, `AT+COPS?`.

Полный автоматический аудит по SMS намеренно не запускается, чтобы не отправить сотни сообщений. Любую команду можно отправить выборочно или пакетным сценарием.

## Возможности GUI

### Команды (158)

Полный каталог без скрытых пунктов. Для каждой команды отображаются группа, тип, уровни П/О, обработчик прошивки и описание. Доступны:

- `get` — чтение;
- `set` — запись значения;
- выполнение команд типа «действие»;
- свободная строка протокола;
- готовые значения для enum/флагов/дат;
- паспорт прибора, пре-флайт, чтение показаний и Auth-scan.

Указанный в интерфейсе уровень доступа не подменяет проверку прибора: окончательное решение принимает прошивка после реальной аутентификации.

### Полный/экспертный доступ

Экспертный режим открывает все критические записи и действия, включённые в протокол: актуатор, сервисные операции, объёмы, параметры связи, пароли, очистки и сбросы. Он включается явным подтверждением на текущую сессию. Аппаратную аутентификацию и права прошивки программа не обходит.

### Транспорт · RAW · SMS

- обычный командный терминал;
- точная передача произвольных HEX-байтов без автоматического кадрирования;
- отображение сырого ответа;
- AT-консоль GSM-модема;
- получение входящих SMS.

RAW HEX доступен только при включённом экспертном режиме.

### Телеметрия

- TCP-приёмник телеметрии прибора;
- сохранение исходного пакета и разобранного JSON;
- формирование ACK `DATA ACCEPT:n`;
- разбор записей, CRC16 и auth/MD5;
- сбор пакета из фактически снятых показаний;
- реальная отправка пакета на указанный host:port.

### История и flash

- загрузка бинарного дампа W25Q64;
- разбор чекпоинта показаний;
- поиск и разбор главного архива;
- разбор журнала событий;
- проверка дублированных значений и экспорт CSV.

### Снимки, сценарии и мониторинг

- безопасный READ-аудит всего каталога;
- фиксация всех 158 позиций, включая отметки команд-действий;
- экспорт JSON/CSV;
- сравнение с загруженным эталоном;
- пакетные сценарии `READ`, `SET`, `ACTION`, `SLEEP`;
- проверка сценария без выполнения;
- остановка выполняемой последовательности;
- периодическое чтение выбранных параметров и экспорт CSV.

## Запуск

### Windows

1. Установить Python 3 с Tkinter.
2. В папке проекта выполнить:

```bat
py -3 -m pip install -r requirements.txt
start_gui.bat
```

### Linux

```bash
python3 -m pip install -r requirements.txt
./start_gui.sh
```

Для Linux обычно также нужен пакет `python3-tk`, а пользователь должен иметь доступ к `/dev/ttyUSB*` или `/dev/ttyACM*`.

## Командная утилита

`smt_cli.py` позволяет работать без GUI.

```bash
# Оптопорт: чтение
python smt_cli.py serial COM3 --get DevInfo

# Оптопорт: критичная команда после аппаратной аутентификации
python smt_cli.py serial COM3 --send "SERVER_URL=10.0.0.5:40000" --expert

# Полный READ-аудит в JSON
python smt_cli.py serial COM3 --scan-all sessions/full_snapshot.json

# TCP-шлюз
python smt_cli.py tcp 192.168.1.50 40000 --get STATUS_SYSTEM

# GSM-модем
python smt_cli.py sms COM7 +79990000000 --at AT+CSQ
python smt_cli.py sms COM7 +79990000000 --send DevInfo
python smt_cli.py sms COM7 +79990000000 --inbox
```

## Безопасная последовательность работы с прибором

1. Проверить электрические уровни и распиновку оптоголовки.
2. Подключиться и получить корректный `DevInfo`.
3. Выполнить «Пре-флайт» и снять паспорт.
4. Сохранить исходный полный снимок.
5. Аутентифицироваться штатными учётными данными.
6. Включать экспертный режим только перед необходимой записью.
7. После изменения повторно прочитать параметр и сохранить журнал сессии.

## Структура

| Файл | Назначение |
|---|---|
| `smt_gui.py` | GUI, реальные транспорты, телеметрия, история, сценарии |
| `smt_client.py` | Serial/оптопорт, TCP, GSM/SMS, экспертный гейт |
| `smt_cli.py` | командная утилита для всех транспортов |
| `smt_commands.json` | каталог 158 команд |
| `smt_tools.py` | снимки, сравнение, пакетные сценарии |
| `smt_session.py` | журнал сессии JSONL/CSV с маскированием секретов |
| `smt_server.py` | приём и разбор телеметрии |
| `smt_state.py`, `smt_eventlog.py`, `smt_smart.py` | анализ flash-данных |
| `optic_preflight.py` | отдельная диагностика оптопорта |

Автоматические тесты не заменяют проверку с конкретной версией прошивки и реальным оборудованием.
