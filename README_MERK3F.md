# MERK-3F — прямая работа с SPI FRAM

Переделка `srt_mod_final.py` с файлов на работу напрямую с памятью через
программатор CH341 в режиме SPI.

| Вкладка | Микросхемы | Объём |
|---|---|---|
| **ART** | MB85RS256 / MB85RS128 / MB85RS64 | 32 / 16 / 8 КБ |
| **AR** | FM25L04B | 512 байт |
| **231-AT-01** | FM25V02 | 32 КБ |

## Как работает

Вместо «открыть .bin → сохранить patched-файл»:

1. **Прочитать из памяти** — микросхема вычитывается целиком, записи
   разбираются, поля заполняются.
2. Правите значения — расчёты те же, что были.
3. **Записать в память** — пишутся только изменившиеся байты, сразу
   идёт проверка чтением.

Кнопка **Определить** читает идентификатор и проверяет реальный объём:
если под профилем MB85RS256 стоит микросхема меньше, адреса
заворачиваются, и программа об этом скажет.

## Только нужные байты

Требование «остальные данные не трогать» выполнено буквально и проверено
тестом: эмулятор запоминает каждый адрес, до которого дошла команда
записи, и сверяется множество адресов, а не только содержимое — байт можно
перезаписать тем же значением, содержимое совпадёт, а ячейка будет
затронута.

Результат прогона:

```
ART         изменено  35 байт, затронуто  35
AR          изменено  14 байт, затронуто  14
231-AT-01   изменено 160 байт, затронуто 160
```

Числа совпадают — ни один неизменившийся байт под команду записи не попал.
Соседние участки правок намеренно **не склеиваются** через неизменные
байты: `changed_ranges` режет буфер строго по границам различий.

Повторная запись тех же значений не отправляет ни одной команды записи.

## FM25L04B — отдельный случай

У неё 512 байт, но адресный байт всего один. Девятый бит адреса (A8) едет
в **бит 3 самой команды**:

```
READ  = 0x03 | (A8 << 3)      адрес 0x0FF → 03 FF
WRITE = 0x02 | (A8 << 3)      адрес 0x100 → 0B 00
```

Без этого вся верхняя половина писалась бы поверх нижней — а дубль записи
как раз лежит по 0x0100. Чтение и запись через границу 0x100 режутся на
две посылки. Проверено тестом.

## Протокол

Команды: WREN 0x06, WRDI 0x04, RDSR 0x05, WRSR 0x01, READ 0x03,
WRITE 0x02, RDID 0x9F.

WREN отправляется перед **каждой** командой записи: бит разрешения
сбрасывается аппаратно после каждой. У FRAM нет цикла стирания и нет
страничных границ, поэтому задержек и постраничной нарезки не требуется —
в отличие от EEPROM.

CH341 переводится в SPI через `CH341SetStream` с битом 7 (старший бит
вперёд). Обмен идёт через `CH341StreamSPI4` — полный дуплекс, буфер
уходит на запись и им же возвращается принятое.

## Версия без 231-AT-01

Состав вкладок — параметр, а не отдельная копия программы:

```python
MainWindow(("ART", "AR"))        # или ALL_TABS для полного набора
```

`merk3f_2tabs.py` — точка входа урезанной версии, десять строк поверх
общего кода. Виджет ненужной вкладки не создаётся вовсе: иначе он остался
бы без родителя и всплыл отдельным окном.

```
python srt_mod_spi.py     ART · AR · 231-AT-01
python merk3f_2tabs.py    ART · AR
```

## Что видно снаружи

Внизу окна показывается только то, что нужно оператору. Внутренние
подробности — CRC, смещения записей, состояние дубля, зеркала,
коэффициенты, счётчики байт — наружу не выводятся.

| Событие | Сообщение |
|---|---|
| Микросхема определена | `Микросхема определена, связь есть` |
| Тип выбран неверно | `Выбран неверный тип микросхемы` |
| Нет программатора | `Нет связи с программатором` |
| Чтение прошло | `Показания прочитаны` |
| Записи в памяти битые | `Данные в памяти повреждены` |
| Запись прошла | `Записано и проверено` |
| Значения не менялись | `Показания не изменились` |
| Запись не подтвердилась | `Запись не подтвердилась. Повторите` |
| Не считали перед записью | `Сначала считайте показания` |

Проверено тестом: после чтения и после записи в тексте статуса не должно
встречаться `CRC`, `0x`, `байт`, `дубль`, `зеркал`, `коэф` и подобного.

Сама логика при этом не изменилась — CRC по-прежнему считается и
проверяется, дубли обновляются, целостность контролируется. Просто
результат сводится к одной понятной строке.

## Сборка exe

Положите рядом `CH341DLLA64.dll` (для 64-битного Python) или `CH341DLL.dll`
и запустите .bat двойным щелчком:

| Версия | Файл сборки | Результат |
|---|---|---|
| Все вкладки | `build_merk3f_full.bat` | `dist\MERK-3F.exe` |
| Без 231-AT-01 | `build_merk3f_2tabs.bat` | `dist\MERK-3F_2tabs.exe` |

Либо напрямую:

```cmd
pip install PyQt5 "pyinstaller>=6.0"
pyinstaller --noconfirm --clean merk3f_full.spec
```

Имя exe и точка входа задаются двумя строками в начале spec:

```python
APP_NAME = "MERK-3F"
ENTRY = "srt_mod_spi.py"
```

### Два места, где сборка ломается молча

**CH341DLL грузится по голому имени.** В onefile-сборке файлы распакованы
во временную папку `sys._MEIPASS`, которой нет в путях поиска DLL, —
загрузка падает. Runtime-хук `pyi_rth_ch341.py` находит библиотеку и
подставляет её полный путь в переменную окружения `CH341DLL`; `spi_memory`
читает эту переменную первой. Заданное вручную значение хук не перетирает,
а если DLL в сборку не клали — молча ничего не делает.

**Заставку PyInstaller рисует tkinter.** Вносить его в `excludes` нельзя,
иначе сборка обрывается с `Your platform does not support the splash
screen feature`. На Windows он идёт в комплекте с python.org. Если
tkinter всё же нет, spec это замечает и собирается без заставки.

### Почему .bat написан транслитом

cmd читает .bat побайтово и запоминает позицию в файле. `chcp` посреди
исполнения меняет кодировку, позиция перестаёт совпадать с границами
символов, строки режутся внутри буквы, а обрывки уходят на исполнение как
команды. Поэтому файлы — **чистый ASCII с CRLF**, без `chcp`:
однобайтовая кодировка рассинхронизироваться не может ни при какой
кодовой странице консоли.

## Файлы

```
srt_mod_spi.py          программа (все вкладки)
merk3f_2tabs.py         точка входа без 231-AT-01
merk3f_full.spec        сборка полной версии
merk3f_2tabs.spec       сборка без 231-AT-01
build_merk3f_full.bat   сборка полной версии в один клик
build_merk3f_2tabs.bat  сборка без 231-AT-01 в один клик
pyi_rth_ch341.py        runtime-хук: путь к CH341DLL в onefile-сборке
spi_memory.py           SPI-бэкенд: CH341SPI + SPIFram + профили микросхем
make_icon.py            генератор иконок (темы integra101 и srt)
splash_screen.py        экран загрузки, палитра и подписи настраиваются

test_spi_memory.py      протокол на эмуляторе FRAM
test_spi_pointwise.py   точечность записи
test_srt_spi_gui.py     вкладки целиком: чтение → правка → запись
```

Транспорт отделён от протокола: `SPIFram` принимает любой объект с
`transfer(bytes) -> bytes`. В работе это `CH341SPI`, в тестах — эмулятор
микросхемы. Поэтому весь протокол проверен без железа.
