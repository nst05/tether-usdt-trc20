# CRC-16 CCITT Storage Editor 🔐

Полный пакет утилит для работы с бинарными файлами, содержащими значения с контрольными суммами **CRC-16 CCITT**.

## 📦 Что это?

**Результат анализа:** Вы попросили разобраться, как число **9442.36** хранится в бинарном файле и как вычисляется его контрольная сумма.

**Найдено:**
- ✓ Позиция: `0x01C1` в файле
- ✓ Представление: Fixed-Point (9442.36 × 100 = 944236)
- ✓ Формат: Big-Endian, 4 байта
- ✓ CRC: **0xAC55** (CRC-16 CCITT)

**Результат:** Полный пакет программ для работы с таким форматом!

## 🎯 Созданные программы

### 1. **GUI Приложение** ⭐

python crc_storage_gui.py

### 2. **CLI Утилита** 💻
```bash
python crc_storage_cli.py list file.bin

```
Быстрая работа из командной строки.

### 3. **Интерактивный редактор** 🔄
```bash
python crc_storage_interactive.py
```
Полный цикл в консоли: считали → увидели → выбрали → ввели → записали.

**Шаги:**
1. Загрузка файла
2. Поиск значений (проверка CRC)
3. Просмотр таблицы значений
4. Выбор значения по номеру
5. Ввод нового значения + подтверждение
6. Сохранение с резервной копией

### 4. **Дамп-редактор** 🧬
```bash
python crc_storage_dump.py dump file.bin -o 0x1C0 -n 128   # hex-дамп
python crc_storage_dump.py write file.bin 0x1C1 00 0E 68 6C # прямая запись байт
python crc_storage_dump.py value file.bin 0x1C1 9442.36     # значение + CRC
python crc_storage_dump.py check file.bin 0x1C1             # проверка CRC
python crc_storage_dump.py find  file.bin 00 0E 68 6C       # поиск байт
python crc_storage_dump.py edit  file.bin                   # интерактивный режим
```

Открывает дамп напрямую и пишет байты по смещению. Размер файла не меняется,
пишутся ровно указанные байты. В GUI это вкладка **«Дамп (прямая запись)»**:
hex-просмотр с постраничной навигацией, поиск байт, прямая запись,
запись значения с CRC, отмена и сброс изменений.

**Команды интерактивного режима:**
```
d [смещение] [длина]     Показать дамп
w <смещение> <hex>       Прямая запись байт
v <смещение> <значение>  Записать значение + CRC
c <смещение>             Проверить CRC блока
f <hex>                  Найти байты
diff                     Показать изменённые байты
undo                     Отменить последнюю запись
save                     Сохранить (создаётся .bak)
```

## 📋 Алгоритм

### CRC-16 CCITT
```
Полином:        0x1021
Инициализация:  0xFFFF
Отражение:      НЕТ
Final XOR:      0x0000
```

### Представление данных
```
Формат:   Fixed-Point (value × 100)
Порядок:  Big-Endian (старший байт первым)
Размер:   4 байта (32-бит)
Диапазон: 0.00 – 42949672.95
```

### Структура хранения (40 байт + 2 CRC)
```
Байты 0–3:    Значение (4 байта)
Байты 4–7:    Дубль (резервная копия)
Байты 8–39:   Паддинг нулями (32 байта)
────────────────────────────────
Затем:        CRC-16 (2 байта, big-endian)
```

## 💡 Python примеры

### Вычисление CRC
```python
from crc_storage_cli import make_block, crc16_ccitt

value = 9442.36
block, crc = make_block(value)
print(f"CRC-16 CCITT для {value}: 0x{crc:04X}")
# Вывод: CRC-16 CCITT для 9442.36: 0xAC55
```

### Работа с файлом
```python
from crc_storage_cli import StorageFile

storage = StorageFile('data.bin')
storage.load()

# Просмотр
for item in storage.values:
    print(f"0x{item['pos']:06X}: {item['value']:.2f} (CRC: 0x{item['crc']:04X})")

# Изменение
storage.write_value(0x01C1, 9999.99)
storage.save()
```

## 🎓 Как это работает?

### Пример для значения 9442.36:

```
1. Исходное значение:        9442.36

2. Умножаем на 100:          944236

3. Переводим в HEX:          0x000E686C

4. В байтах (big-endian):    00 0E 68 6C

5. Создаём 40-байтовый блок:
   00 0E 68 6C    ← значение
   00 0E 68 6C    ← дубль (резервная копия)
   00 00 ... 00   ← паддинг (32 байта нулей)

6. Вычисляем CRC-16 CCITT:   0xAC55

7. Результат в файле:
   0x01C1: 00 0E 68 6C 00 0E 68 6C 00 00 ... AC 55
```

---

## ⚠️ Важные моменты

1. **Точечность** — меняются ТОЛЬКО 42 байта (40 блок + 2 CRC)
2. **Резервирование** — перед сохранением создаётся .bak
3. **Валидация** — все CRC проверяются при загрузке
4. **Big-Endian** — старший байт первым в 4-байтовом значении
5. **Fixed-Point** — значение всегда умножается на 100
