# VF Gen — генератор прошивок ce101 r5 145

Доработка старой программы `GEN_VF_w_v1.py`: тот же формат прошивки, но
берёт **любое** число, полный диапазон, оформление с анимацией запуска,
счётчик сохранённых файлов и привязка к компьютеру.

## Файлы

| Файл              | Назначение                                             |
|-------------------|--------------------------------------------------------|
| `vf_gen.py`       | программа (окно, подбор, сохранение .hex)               |
| `vf_core.py`      | математика формата ce101 r5 145 (подбор и Intel HEX)    |
| `vf_license.py`   | код компьютера, ключи активации, проверка               |
| `vf_counters.py`  | счётчик сохранённых файлов                               |
| `vf_storage.py`   | хранение `license_vf.key` и `counters_vf.json`          |
| `keygen_vf.py`    | генератор ключей — **только для вас**                    |
| `compile_core.py` | компиляция ядра в нативный модуль (защита исходника)     |
| `vf_gen.spec`     | сборка программы в один `.exe`                           |
| `keygen_vf.spec`  | сборка генератора ключей в `.exe`                        |
| `build_all.bat`   | собрать всё сразу                                        |

## Авторежим (ввёл → «Записать в прибор»)

Главная кнопка **«ЗАПИСАТЬ В ПРИБОР»** (или Enter в поле) делает всё за один
шаг: подбирает байты → собирает .hex → шьёт **только EEPROM** PIC16F1934
через PICkit 3 (`ipecmd -ME`, основная прошивка не стирается). Счётчик
«ЗАПИСАНО» растёт только при успешной записи. Кнопка «Только подобрать»
оставлена для проверки/сохранения .hex без прошивки.

Требуется **MPLAB IPE** (ipecmd.exe): установите MPLAB X **v6.15 или старее**
(в v6.20+ PICkit 3 не поддерживается). Программа находит ipecmd сама; можно
задать путь вручную через переменную окружения `IPECMD`.

Настройки прошивки — вверху `vf_gen.py`:
`PIC_DEVICE` (16F1934), `PIC_TOOL` (PPK3 = PICkit 3; PPK4/PPK5 для 4/5),
`EEPROM_ONLY` (True — только EEPROM), `POWER_FROM_TOOL`, `VDD`.

## Запуск из исходников

```bash
pip install -r requirements.txt
python vf_gen.py
```

## Сборка .exe

Проще всего — `build_all.bat`. Вручную:

```bat
python -m pip install -r requirements.txt pyinstaller
python compile_core.py                    (защита ядра, опционально)
python -m PyInstaller vf_gen.spec         ->  dist\VF_Gen.exe
python -m PyInstaller keygen_vf.spec      ->  dist\keygen_vf.exe
```

Клиенту отдаётся один файл `dist\VF_Gen.exe`. `keygen_vf.exe` оставляете себе.

## Что доработано в математике

Старая программа «не все числа» выдавала по трём причинам — все устранены.

1. **Дробный блок был скрыт.** Показание без него всегда кратно `0.85`,
   поэтому точно попасть в целое число получалось лишь в ~6% случаев
   (средняя ошибка 0.36, до 1.2). Дробный блок `0x1E200` с шагом `0.03`
   даёт **точное** попадание в любое число — теперь он включён по
   умолчанию (галочка «Дробный блок»). Проверено: 100% попаданий на
   тысячах случайных значений, ошибка 0.00.
2. **Диапазон был срезан** ограничением `b3 ≤ 0x0F` (потолок 891 297.25).
   Галочка «Полный диапазон» снимает его — потолок 14 260 641.25.
3. **Слабый перебор idx** (только floor/ceil) заменён на поиск по окну,
   поэтому решение находится всегда, а не пропускается.

Формула восстановлена по вашим дампам и совпадает с ними **байт в байт**
(`__7035`, `__7037`, `__7038`, `__7044`, `__0`):

```
R = 0.85·idx(b1) + 435.20·(b2÷2) + 5.95·(b2 и 1)
              + 111411.20·(b3÷2) + 2.55·(b3 и 1) + 0.03·N
idx(b1) = (b1 без битов 0x06) + 256·бит0x04 + 65536·бит0x02
```

В файл, как и в оригинале, триплет пишется с перестановкой: `[b1, b3, b2]`.

## Счётчик

Считает сохранённые `.hex`. Хранится в `counters_vf.json` рядом с
программой, растёт только при успешном сохранении, переживает перезапуск,
защищён контрольной суммой от ручной правки. Сброс — только удалением файла.

## Привязка к компьютеру

При первом запуске — окно активации с кодом ПК
(`B15C0-434B2-B000A-6E8A7`). Клиент присылает код, вы делаете ключ:

```bash
python keygen_vf.py B15C0-434B2-B000A-6E8A7            # бессрочно
python keygen_vf.py B15C0-434B2-B000A-6E8A7 --days 365 # на год
python keygen_vf.py --my-code                          # код текущего ПК
```

Ключ подписан HMAC-SHA256 от кода компьютера: на другом ПК не работает,
скопированный `license_vf.key` тоже. Проверка — при запуске, перед каждым
сохранением и раз в час. Без лицензии кнопки «Сохранить» отказывают.

## Защита от извлечения исходного кода

Требование выполнено в три слоя:

1. **Нативное ядро.** `compile_core.py` компилирует `vf_core.py`
   (всю логику формата) через Cython в машинный код (`.pyd`). В exe это
   обычный C-модуль — декомпиляторы Python (`uncompyle6`, `decompyle3`,
   `pycdc`) его не восстанавливают. Нужен компилятор C: на Windows —
   бесплатный «Build Tools for Visual Studio». Если его нет, сборка всё
   равно проходит, но ядро останется байт-кодом (см. слой 2).
2. **Байт-код Python 3.13.** Даже без Cython публичные декомпиляторы
   на момент выпуска формат 3.13 не разбирают — из exe достаётся лишь
   `.pyc`, не читаемый как исходник. Собирайте на свежем Python.
3. **Секрет лицензии не в ядре.** Ключи проверяются в `vf_license`,
   секрет замените перед сборкой (см. ниже).

Полностью «непробиваемой» защиты для локального exe не существует —
при большом желании нативный код дизассемблируют. Но перечисленное
отсекает простое извлечение исходника и делает вскрытие несопоставимо
трудоёмким. Максимальный уровень (нативное ядро) требует лишь один раз
поставить Build Tools — рекомендую это сделать.

## ОБЯЗАТЕЛЬНО перед распространением: смените секрет

В `vf_license.py`:

```python
DEFAULT_SECRET = 'vf-gen-license-secret-change-me-2024'
```

Замените на свою случайную строку и пересоберите **оба** exe с одним
секретом (у программы и генератора он должен совпадать), иначе ключи не
подойдут. Можно не править файл, а задать `VF_LICENSE_SECRET` при сборке.
