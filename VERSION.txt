ГЛАВНОЕ В ЭТОЙ ВЕРСИИ: ИСПРАВЛЕНА АДРЕСАЦИЯ I2C
════════════════════════════════════════════════════════════════════════════════

Симптом до 2.3:
  «Ошибка: Проверка записи не пройдена (10 попыток)»
  Чтения возвращали мусор: FFFFFFFF, 1111000000FFFFFF, 00111111000000FF

Причина (ошибка в коде, НЕ в железе):
  Модуль использовал схему адресации 24C16, скопированную из MT_Writer,
  хотя работал с 24C256. Микросхема ждала ДВА адресных байта, получала
  ОДИН, и адрес каждый раз уезжал на произвольное место.

  Доказательство: возвращаемые «мусорные» байты — это реальное содержимое
  области 0x0030-0x0040 микросхемы (00 00 11 11 11 00 00 00 FF FF ...).
  Шина работала исправно, сломана была адресация.

Различие схем:
┌──────────────────┬───────────────────┬────────────────────┐
│                  │ 24C16 (MT_Writer) │ 24C256 (наш дамп)  │
├──────────────────┼───────────────────┼────────────────────┤
│ Объём            │ 2 КБ (2048)       │ 32 КБ (32768)      │
│ Адресов на шине  │ 8 (0x50-0x57)     │ 1 (0x50)           │
│ Адрес памяти     │ 8 бит             │ 16 бит             │
│ Страница записи  │ 16 байт           │ 64 байта           │
└──────────────────┴───────────────────┴────────────────────┘

════════════════════════════════════════════════════════════════════════════════
ЧТО ИСПРАВЛЕНО
════════════════════════════════════════════════════════════════════════════════

1. 16-БИТНАЯ АДРЕСАЦИЯ ПАМЯТИ
   Один адрес устройства 0x50, адрес памяти передаётся двумя байтами
   (addrsize=16). Схема с блоками сохранена только для 24C16/08.

2. ПОСТРАНИЧНАЯ ЗАПИСЬ
   Второй скрытый баг: 42 байта писались ОДНОЙ транзакцией. EEPROM не умеет
   писать через границу страницы — адрес заворачивается ВНУТРИ страницы и
   затирает уже записанные байты. Теперь payload режется по границам
   страницы с паузой tWR (10 мс) между страницами.

3. СМЕЩЕНИЕ БЛОКА ПО УМОЛЧАНИЮ 0x01C1
   Было 0x0000 — там пусто, отсюда «Текущее значение: 0.00».
   В дампе запись реально лежит на 0x01C1:
     0x01C1  значение   00 0E 68 6C
     0x01C5  дубль      00 0E 68 6C
     0x01C9  паддинг    32 нулевых байта
     0x01E9  CRC-16     AC 55   ✓ сошёлся

4. ПРОФИЛИ МИКРОСХЕМ
   24C256 / 24C128 / 24C64 / 24C32 / 24C16 / 24C08
   Для каждой: объём, разрядность адреса, размер страницы.

5. АВТООПРЕДЕЛЕНИЕ ЧИПА — кнопка «Определить чип»
   Опрашивает адреса 0x50-0x57 и смотрит, сколько откликнулось:
     • один адрес       → 24C256/128/64/32 (16-битный адрес памяти)
     • несколько адресов → 24C16/08 (8-битный адрес + блоки)
   Дополнительно перепроверяет стабильность чтения, если в памяти есть
   содержательные данные. На пустой памяти (сплошные FF) работает только
   опрос адресов — поэтому он и сделан главным признаком.

6. ВЫБОР МИКРОСХЕМЫ В GUI
   Выпадающий список на вкладке I2C. Если у вас реально 24C16 (как в
   MT_Writer) — выберите его, программа переключит схему.

7. РАСШИРЕННОЕ ЛОГИРОВАНИЕ
   Лог теперь показывает конфигурацию (чип, разрядность адреса, размер
   страницы, смещение) и каждую записанную страницу отдельно.

ФОРМАТ ХРАНЕНИЯ (без изменений)
════════════════════════════════════════════════════════════════════════════════

  Алгоритм CRC:  CRC-16 CCITT
  Полином:       0x1021
  Инициализация: 0xFFFF
  Отражение:     нет
  Final XOR:     0x0000

  Значение:      fixed-point, value × 100, 4 байта BIG-ENDIAN
  Блок:          40 байт (значение + дубль + 32 байта паддинга)
  CRC:           2 байта BIG-ENDIAN следом
  Итого:         42 байта на запись
