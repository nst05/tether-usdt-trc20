# Контроллер устройства 4.5.4 DIAGNOSTIC LOG

Программа предназначена для работы **с реальным прибором**. Виртуальных устройств и подмены ответов в проекте нет. Каталог содержит **158 команд** прошивки: чтение параметров, разрешённая уровнем доступа запись, сервисные действия, работа с актуатором, связью, архивами, телеметрией и диагностикой.

## Реальные каналы связи

### USB-оптопорт / Serial

Поддерживаются:

- произвольный COM/tty-порт и скорость от 300 до 230400 бод;
- 5/6/7/8 бит данных, чётность N/E/O/M/S, 1/1.5/2 стоп-бита;
- XON/XOFF, RTS/CTS, DSR/DTR и явные уровни DTR/RTS;
- кадрирование `cr`, `crlf`, `brace`, `iec` или автоматическое определение по `DevInfo`;
- настройка таймаута ответа, межбайтовой паузы и повторов безопасного чтения;
- автоматическое удаление точного оптического эха из разбираемого ответа;
- сохранение реальных TX/RX-байтов и задержки каждого обмена.

### TCP-шлюз

Командный request/response через реальный TCP-шлюз: host, port, таймаут и окончание команды `нет/CR/LF/CRLF`. Каталог, экспертный режим, журналирование, сценарии, снимки и мониторинг работают так же, как через оптопорт.

### GSM / SMS

Работа через физический GSM-модем с AT-интерфейсом:

- отправка команд SMS;
- собственный префикс команды;
- чтение непрочитанных SMS и опциональное удаление;
- ручные AT-команды, например `AT+CSQ`, `AT+CREG?`, `AT+COPS?`.

Полный автоматический аудит по SMS намеренно не запускается, чтобы не отправить сотни сообщений. Любую команду можно отправить выборочно или пакетным сценарием.

## Возможности GUI

### Команды (158)

Полный каталог без скрытых пунктов. Для каждой команды отображаются группа, тип, уровни П/О, обработчик прошивки и описание. Доступны:

- `get` — чтение;
- `set` — запись значения;
- выполнение команд типа «действие»;
- свободная строка протокола;
- готовые значения для enum/флагов/дат;
- паспорт прибора, пре-флайт, чтение показаний и Auth-scan.

Уровень Provider в интерфейсе выставляется после штатной команды `PASSWORD_PROVIDER=…`, когда прибор вернул непустой ответ без распознанного отказа (`ERROR`, `DENIED`, `INCORRECT_PASSWORD`, `NAK` и т. п.). Дополнительная команда `PASWORD_PROVID_VALUE` автоматически не отправляется. Состояние действует на текущем подключении и сбрасывается при отключении; окончательное решение по каждой команде всё равно принимает прошивка прибора.

### Полный/экспертный доступ

Экспертный режим открывает программный гейт критических записей и действий: актуатор, сервисные операции, объёмы, параметры связи, пароли, очистки и сбросы. Кнопка прямой записи показаний использует подтверждённую Provider-сессию. Свободный терминал и CLI не подменяют права: они передают команду, а окончательное решение принимает прошивка. Программа не подбирает пароль и не обходит аппаратную аутентификацию.

### Транспорт · RAW · SMS

- обычный командный терминал;
- точная передача произвольных HEX-байтов без автоматического кадрирования;
- отображение сырого ответа;
- AT-консоль GSM-модема;
- получение входящих SMS.

RAW HEX доступен только при включённом экспертном режиме.

### Телеметрия

- TCP-приёмник телеметрии прибора и ACK `DATA ACCEPT:n`;
- сохранение исходного пакета и разобранного JSON;
- постоянная база `sessions/telemetry.sqlite3`;
- дедупликация одинаковых пакетов по SHA-256;
- накопление телеметрии от нескольких устройств по ID64;
- статистика пакетов, записей, устройств и аномалий;
- автоматические признаки: уменьшение накопителя, возврат времени, ненулевой флаг;
- фильтр «только аномалии» и экспорт всей базы CSV;
- разбор CRC16 и auth/MD5;
- сбор пакета из фактически снятых показаний и отправка на host:port.

### История и flash

- загрузка бинарного дампа W25Q64;
- разбор чекпоинта, главного измерительного архива и журнала событий;
- проверка зеркальной копии показания;
- обнаружение отката времени, индекса и накопленного объёма;
- фильтр аномалий и общий экспорт CSV;
- локальный журнал «корректировок» не создаётся.

### Прямая Provider-запись показаний

Для `Volume`, `VOLUME_GLOB`, `VOLUME_COMMIS` и `VOLUME_DISC` предусмотрена прямая запись:

1. оператор вводит действующий пароль Provider;
2. программа отправляет `PASSWORD_PROVIDER=…`;
3. программа проверяет ответ самой команды пароля на пустой ответ и известные признаки отказа;
4. отправляется ровно одна команда `NAME=value`;
5. при включённом флажке выполняется read-back; флажок можно отключить.

Искусственного 15-минутного таймера, обязательных полей «оператор/причина» и автоматической очистки архива нет. Provider-состояние действует до отключения или повторной авторизации.

`CLEAR_ARHIVE` остаётся самостоятельной критической командой каталога. Её можно отправить через каталог, свободный терминал или CLI в экспертном режиме; программа не сцепляет её с записью показаний.

По SMS пароль и команды отправляются через GSM-модем. Ответ `+CMGS/OK` подтверждает отправку модемом, а не выполнение прибором, поэтому подтверждение результата нужно получать отдельным входящим SMS.

### Снимки, сценарии и мониторинг

- безопасный READ-аудит всего каталога;
- фиксация всех 158 позиций, включая отметки команд-действий;
- экспорт JSON/CSV;
- сравнение с загруженным эталоном;
- пакетные сценарии `READ`, `SET`, `ACTION`, `SLEEP`;
- проверка сценария без выполнения;
- остановка выполняемой последовательности;
- периодическое чтение выбранных параметров и экспорт CSV.

## Запуск

### Windows

1. Установить Python 3 с Tkinter.
2. В папке проекта выполнить:

```bat
py -3 -m pip install -r requirements.txt
start_gui.bat
```

### Linux

```bash
python3 -m pip install -r requirements.txt
./start_gui.sh
```

Для Linux обычно также нужен пакет `python3-tk`, а пользователь должен иметь доступ к `/dev/ttyUSB*` или `/dev/ttyACM*`.

## Командная утилита

`smt_cli.py` позволяет работать без GUI.

```bash
# Оптопорт: чтение
python smt_cli.py serial COM3 --get DevInfo

# Оптопорт: критичная команда после аппаратной аутентификации
python smt_cli.py serial COM3 --send "SERVER_URL=10.0.0.5:40000" --expert

# Полный READ-аудит в JSON
python smt_cli.py serial COM3 --scan-all sessions/full_snapshot.json

# TCP-шлюз
python smt_cli.py tcp 192.168.1.50 40000 --get STATUS_SYSTEM

# GSM-модем
python smt_cli.py sms COM7 +79990000000 --at AT+CSQ
python smt_cli.py sms COM7 +79990000000 --send DevInfo
python smt_cli.py sms COM7 +79990000000 --inbox

# Прямая Provider-запись с read-back
set SMT_PROVIDER_PASSWORD=пароль
python smt_cli.py serial COM3 --set-reading 1234.5678 --expert

# Та же запись без read-back
python smt_cli.py serial COM3 --set-reading 1234.5678 --expert --no-readback

# Самостоятельная очистка архива
python smt_cli.py serial COM3 --send CLEAR_ARHIVE --provider-password пароль --expert
```

## Безопасная последовательность работы с прибором

1. Проверить электрические уровни и распиновку оптоголовки.
2. Подключиться и получить корректный `DevInfo`.
3. Выполнить «Пре-флайт» и снять паспорт.
4. Сохранить исходный полный снимок.
5. Аутентифицироваться штатными учётными данными.
6. Включать экспертный режим только перед необходимой записью.
7. Для показаний использовать Provider-кнопку или свободную команду; read-back включать по необходимости. `CLEAR_ARHIVE` отправлять отдельно только когда действительно нужна очистка.

## Полный диагностический журнал v4.5.4

При каждом запуске GUI, CLI и TCP-сервера автоматически создаются файлы в `diagnostics/`:

- `diagnostic_*.jsonl` — полные структурированные события;
- `diagnostic_*.log` — человекочитаемая последовательность;
- CSV формируется из вкладки **«Диагностика · все действия»** или меню **«Сессия»**.

Фиксируются нажатия и ввод в GUI, параметры задач, подключение/отключение, авторизация,
команды, полный TX/RX без маскирования и обрезания, RAW HEX, AT/SMS, телеметрия,
результаты парсинга, ошибки с traceback, потоки и длительность операций.

**Важно:** диагностический журнал намеренно содержит полные пароли, команды, номера,
пакеты и ответы прибора. Храни его как технические данные ограниченного доступа.
