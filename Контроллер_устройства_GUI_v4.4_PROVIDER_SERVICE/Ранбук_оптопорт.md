# Ранбук физического оптопорта

## 1. До запуска программы

- USB-оптоголовка определяется операционной системой как serial-порт.
- Порт не открыт терминалом, отладчиком или вторым экземпляром GUI.
- Настройки прошивки и GUI совпадают: по умолчанию `9600 8N1`, без flow control.
- Оптическая головка правильно установлена на передатчик/приёмник прибора.
- Оптопорт прибора включён и не находится в спящем состоянии.

## 2. Быстрая проверка

Windows:

```bat
py -3 optic_preflight.py COM4
```

Linux:

```bash
python3 optic_preflight.py /dev/ttyUSB0
```

Успех означает:

```text
[OK] Кадрирование: cr или crlf/brace/iec
[OK] Задержка ответа:... мс
DevInfo = '...'
```

## 3. Проверка через GUI

1. Нажать «Порты…» и выбрать порт.
2. Оставить кадр `auto`.
3. Нажать «Подключить».
4. Дождаться зелёного статуса.
5. Нажать «Пре-флайт».
6. Прочитать `DEVICE_SN`, `VER_PO`, `STATUS_SYSTEM`.
7. Открыть вкладку raw hex и сохранить журнал.

GUI не показывает «подключено», пока не получит корректный `DevInfo`.

## 4. Интерпретация raw hex

### TX есть, RX пуст

- прибор не отвечает;
- неправильный baud;
- оптопорт спит или выключен;
- нет оптической связи;
- TX/RX или полярность схемы неверны.

### RX повторяет только TX

Оптоголовка видит собственный свет, но ответа прибора нет. Транспорт распознаёт такое само-эхо и не считает его ответом.

### RX содержит TX, затем `NAME=value;`

Нормальное само-эхо. GUI удаляет первую копию только при разборе, а в raw-журнале оставляет полный физический кадр.

### Ответ обрывается

Увеличить межбайтовую паузу:

```bash
SMT_IDLE_GAP=0.5 python3 smt_gui.py
```

### Ответ приходит слишком поздно

```bash
SMT_RESPONSE_TIMEOUT=5 python3 smt_gui.py
```

## 5. Правило повторов

- Чтение параметра можно повторить: оно не меняет состояние.
- Запись и действие автоматически не повторяются.
- Если ответ на запись потерян, сначала прочитать параметр и проверить фактическое состояние.

Это особенно важно для актуатора, сброса, сервиса и изменения паролей.

## 6. Экспертный режим

Экспертный режим интерфейса v3 сохранён. Он разрешает фактическую отправку критической команды, но не подменяет авторизацию прошивки.

Рекомендуемый порядок:

1. Подключиться и сохранить паспорт.
2. Аутентифицироваться штатными данными.
3. Прочитать текущее значение.
4. Включить экспертный режим.
5. Отправить одну команду.
6. Снова прочитать состояние.
7. Сохранить обычный и hex-журнал.

## 7. TCP-телеметрия

1. Разрешить входящий TCP-порт в локальном firewall.
2. Нажать «Слушать» во вкладке «Телеметрия».
3. Указать в приборе IP компьютера и выбранный порт.
4. Дождаться физического подключения GPRS/TCP.
5. Проверить файлы `sessions/session_*.log` и `.json`.
6. Убедиться, что прибор получил ACK `DATA ACCEPT:N`.

## 8. Аппаратная диагностика

Если программная проверка не даёт ответа, измерить:

- наличие питания оптического передатчика/приёмника;
- сигнал UART TX микроконтроллера;
- сигнал после оптического приёмника;
- логический уровень USB-UART;
- длительность бита относительно выбранного baud;
- отсутствие инверсии линии.

Программа видит только байты, дошедшие до serial-драйвера, и не может определить опасный или неправильный электрический уровень.
