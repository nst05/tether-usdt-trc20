# AnonVPN

Учебный, но **полностью рабочий** анонимизирующий VPN-протокол для Linux с
шифрованием современными примитивами и слоем обфускации трафика (anti-DPI).

Снаружи трафик AnonVPN выглядит как равномерный случайный шум поверх UDP: у
датаграмм нет магических байтов, фиксированных заголовков и предсказуемой
структуры. Это мешает провайдеру, локальной сети или DPI-оборудованию понять,
что вы вообще пользуетесь VPN, а тем более — каким именно.

---

## Что это даёт, а что нет (читать обязательно)

VPN — это **один хоп**. Будьте честны с моделью угроз:

**Скрывает:**
- содержимое вашего трафика от локальной сети, Wi-Fi-точки, провайдера;
- ваш реальный IP от сайтов и сервисов, к которым вы обращаетесь (они видят IP
  VPN-сервера);
- сам **факт** использования VPN от пассивного DPI (за счёт обфускации) —
  приложения и сервисы по пути не распознают протокол.

**НЕ скрывает / важные оговорки:**
- **VPN-сервер видит ваш трафик** (до его выхода в открытый интернет). Вы просто
  переносите доверие с провайдера на владельца сервера. Поднимайте свой.
- Это **не Tor**. Настоящая анонимность от самого сервера требует многошаговой
  маршрутизации (несколько независимых узлов). Один VPN этого не делает.
- Активный, целевой анализ (тайминги, корреляция объёмов трафика) обфускация
  полностью не победит. Она рассчитана на массовый пассивный DPI.
- Утечки на уровне приложения (DNS, WebRTC, cookies, логины) VPN не лечит.
  Настройте DNS внутри туннеля и проверьте утечки.

> Для максимума анонимности заворачивайте AnonVPN в Tor или используйте цепочку
> из независимых узлов. Один сервер ≠ анонимность от оператора этого сервера.

**Только для законного использования:** защита приватности, обход цензуры,
тестирование сетей с разрешения владельца. Не используйте для нарушения закона.

## Архитектура

```
 приложение
     │  (обычные IP-пакеты)
     ▼
 ┌─────────┐   читает/пишет сырые IP-пакеты
 │  TUN    │◄──────────────────────────────┐
 └─────────┘                               │
     │                                     │
     ▼                                     │
 шифрование сессии (ChaCha20-Poly1305 AEAD, счётчик-nonce, anti-replay)
     │                                     ▲
     ▼                                     │
 обфускация (XOR-keystream + случайный padding, без сигнатур)
     │                                     │
     ▼                                     │
 UDP ──────────── интернет ──────────────► UDP (сервер) ─► NAT ─► выход
```

### Криптография
- **Обмен ключами:** X25519 (Curve25519 ECDH).
- **Шифрование данных:** ChaCha20-Poly1305 (AEAD), отдельные ключи на каждое
  направление, 64-битный счётчик-nonce (без повторов), скользящее окно
  anti-replay (RFC 6479-style).
- **KDF:** HKDF-SHA256 с доменным разделением.
- **Рукопожатие:** по мотивам WireGuard / Noise IK — взаимная аутентификация по
  статическим ключам, **forward secrecy** за счёт эфемерных ключей, скрытие
  идентичности (статические публичные ключи не передаются в открытом виде).

Криптопримитивы берутся из библиотеки `cryptography` (pyca), которая оборачивает
проверенные C-реализации (OpenSSL/BoringSSL). Свои шифры не пишем.

### Обфускация
Вся датаграмма (включая рукопожатие) гаммируется ChaCha20-keystream'ом по
ключу, выведенному из общего пароля, плюс случайный padding переменной длины.
Цель — отсутствие распознаваемой сигнатуры и сокрытие истинных длин пакетов.

> Обфускация **не** заменяет шифрование. Конфиденциальность обеспечивает AEAD;
> обфускация лишь прячет факт использования VPN.

## Состав

| Файл | Назначение |
|------|-----------|
| `crypto.py` | примитивы: X25519, ChaCha20-Poly1305, HKDF, anti-replay |
| `obfs.py` | слой обфускации (anti-DPI) |
| `protocol.py` | рукопожатие и шифрование сессии |
| `tun.py` | TUN-интерфейс, NAT, форвардинг (Linux) |
| `firewall.py` | kill-switch и защита от утечек DNS (iptables) |
| `server.py` | VPN-сервер |
| `client.py` | VPN-клиент |
| `gui.py` | графический интерфейс клиента (tkinter): кнопки и лог |
| `keygen.py` | генерация ключей |
| `setup_configs.py` | генерация готовых конфигов сервер/клиент |
| `selftest.py` | проверка криптоядра (без root) |
| `inttest.py` | интеграционный тест по UDP loopback (без root) |

## Требования

- Linux (нужен `/dev/net/tun`, `iproute2` и `iptables`).
- Python 3.10+.
- `pip install -r requirements.txt`
- root / `CAP_NET_ADMIN` для поднятия TUN.

## Быстрый старт

### 1. Тесты (root не нужен)
```bash
python -m anonvpn.selftest     # криптоядро
python -m anonvpn.inttest      # полный путь по UDP loopback
```

### 2. Сгенерировать конфиги
На любой машине:
```bash
python -m anonvpn.setup_configs \
    --server-host vpn.example.com \
    --server-port 51820 \
    --out-interface eth0 \
    --obfs-pass "очень-длинный-секретный-пароль" \
    --clients 3 \           # сгенерировать 3 устройства (IP .2, .3, .4)
    --redirect-all \        # завернуть весь трафик клиента в туннель
    --dns 1.1.1.1,1.0.0.1 \ # DNS внутрь туннеля (защита от утечек)
    --kill-switch           # блокировать трафик при обрыве туннеля
```
Появятся `server.conf` и `client1.conf … clientN.conf`. Скопируйте `server.conf`
на сервер, каждый `clientN.conf` — на своё устройство. Пароль обфускации должен
совпадать с обеих сторон.

### 3. Запуск
На сервере:
```bash
sudo python -m anonvpn.server --config server.conf -v
```
На клиенте:
```bash
sudo python -m anonvpn.client --config client.conf -v
```

После подключения проверьте, что внешний IP стал серверным:
```bash
curl https://api.ipify.org
```

### 4. Графический интерфейс (вместо консольного клиента)

GUI на tkinter: поле выбора конфига и кнопка «Обзор», индикатор статуса
(красный/оранжевый/зелёный), кнопки **Подключить / Отключить**, кнопка очистки и
живой цветной лог. GUI сам запускает клиент как отдельный процесс и аккуратно
гасит его при отключении (что откатывает kill-switch и DNS).

```bash
sudo apt install python3-tk      # Debian/Ubuntu (Fedora: python3-tkinter)
sudo python -m anonvpn.gui
```
Если запустить без root, GUI попробует поднять клиент через `pkexec`/`sudo`.

## Защита от утечек

- **DNS (встроено):** при `dns_servers` в конфиге клиент сам бэкапит
  `/etc/resolv.conf` и прописывает указанные резолверы. Вместе с `redirect_gateway`
  DNS-запросы идут зашифрованными через туннель, а не к провайдеру. При выходе
  `resolv.conf` восстанавливается.
- **Kill-switch (встроено):** при `kill_switch: true` клиент правилами `iptables`
  разрешает исходящий трафик только в туннель (`anon0`) и до VPN-сервера; всё
  остальное блокируется. Если туннель падает — трафик не утекает мимо VPN.
  Правила откатываются при выходе (в т.ч. по Ctrl+C / SIGTERM).
- **IPv6:** если в системе включён IPv6, а туннель только IPv4 — отключите IPv6
  или тоже заверните, иначе будет утечка мимо VPN.

## Замечания по безопасности

Это **учебная** реализация: она демонстрирует корректный дизайн (современный
AEAD, forward secrecy, anti-replay, взаимная аутентификация, обфускация), но не
проходила независимый аудит. Для критичных задач используйте проверенные
решения — **WireGuard** (при необходимости с обфускатором вроде
`shadowsocks`/`xray`/`obfs4`). Идеи AnonVPN близки к WireGuard именно потому, что
это удачная, минималистичная и анализируемая модель.
